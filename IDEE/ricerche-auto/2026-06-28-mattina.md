### 5. Come evitare che Claude Code vada fuori strada su un progetto lungo (la tecnica dello spec che funziona anche senza saper programmare)

- **Format**: Problem-solver
- **Angolo nuovo**: Nessun video precedente sul canale ha trattato lo spec-driven development per utenti non tecnici. Il problema è reale e documentato: Claude Code inizia bene su progetti complessi, ma dopo 30-40 minuti inizia a prendere decisioni autonome che non hai chiesto — cambia file, aggiunge funzioni, si inventa soluzioni che non avevi in mente. La causa: nessun documento di riferimento da cui partire. La soluzione non è "saper programmare meglio" — è scrivere uno spec prima di dare il via. Lo spec è un documento di 1-2 pagine in linguaggio naturale che dice a Claude cosa costruire, come, con quali vincoli, e cosa non deve mai fare. La differenza rispetto al CLAUDE.md (coperto indirettamente in precedenza): CLAUDE.md è per le preferenze globali di stile; lo spec è per il progetto specifico che stai costruendo in questo momento.
- **Ispirato da**: [Show HN: Spec-Driven Development Workflow for Claude Code — Hacker News](https://news.ycombinator.com/item?id=48231575) | [Claude Code June 2026: 10 New Features — sitepoint.com](https://www.sitepoint.com/claude-code-june-2026-10-new-features-devs-need-to-know/)
- **Hook potenziale**: "Se hai usato Claude Code per più di un'ora su qualcosa di complicato, sai come va: a un certo punto inizia a fare cose che non avevi chiesto. Cambia roba, aggiunge roba, decide da solo. Non è un bug — è che gli manca una bussola. Ti do il template della bussola."
- **Cosa costruisce concretamente lo spettatore**: Il proprio template di spec — un documento di 1-2 pagine in linguaggio naturale da dare a Claude Code all'inizio di ogni progetto. Include: (1) cosa si sta costruendo e a chi serve; (2) i 3 vincoli che Claude non può mai violare; (3) la lista di cosa è fuori scope; (4) il formato dell'output atteso. Template scaricabile per 3 casi d'uso comuni: mini-tool di analisi, workflow di automazione, sistema di report.
- **Target**: Utenti Claude Code che hanno già superato la fase dei prompt semplici e usano lo strumento per progetti più complessi — ma si ritrovano a correggere continuamente il tiro perché Claude va per conto suo. Non tecnici che vogliono più controllo senza dover imparare a programmare.
