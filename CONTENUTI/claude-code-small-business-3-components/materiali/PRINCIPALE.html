A minimal but real AI infrastructure: a database connected via MCP, the pre-built package Anthropic just released for small businesses, and parallel custom agents. Three pieces that talk to each other.

What an "AI infrastructure" for a small business is

It's not a tool. It's three pieces that talk to each other. If you're missing even one, the AI stays a toy: it does the same thing twice, forgets what it did yesterday, doesn't know where to find a customer's data, can't reuse the work you paid the AI to do last week.

The basic rule: a minimal AI infrastructure has 3 layers. (1) Your data: where the facts specific to your business live — how you categorize clients, how you track deadlines, the quirks your industry has and nobody else does. (2) Common workflows: payroll, invoicing, month close, briefings — things every small business does, and Anthropic has already written them for you. (3) Custom agents: for the things only you do, running in parallel, when the pre-built ones aren't enough.

All three must talk with Claude Code (or with Claude Cowork for the pre-built package). If one piece lives in a silo the AI can't see, the AI can't automate it.

What we'll build today

To demonstrate the pattern we'll use an accounting firm as the example. 50 clients, each with their own tax peculiarities (different regimes, different VAT schedules). Today the firm's junior takes 3 days to do the monthly close. Tomorrow the infrastructure does it in 30 minutes, and the junior reviews it instead of doing it.

COMPONENT 1 — SUPABASE (via MCP) Tables: clients, tax_regimes, custom_deadlines, internal_notes → the SPECIFIC data of the firm that no standard tax software knows about COMPONENT 2 — CLAUDE FOR SMALL BUSINESS (Cowork) Standard workflows: /close-month, /invoice-chaser, /monday-brief Connectors: QuickBooks, Google Workspace, HubSpot, DocuSign, … → handles things common to ALL firms, knows how it's done COMPONENT 3 — AGENT VIEW (Claude Code) Sub-agents: document-classifier, regime-checker, deadline-alerter → the CUSTOM things of the firm, in parallel ────────────────────────────────────────────────── MONDAY MORNING FLOW: /monday-brief → reads QuickBooks + Supabase → summarizes the situation document-classifier (custom) → parses ambiguous documents and updates Supabase /close-month → merges QuickBooks data + custom Supabase data → final report

The same schema works for any small business where you have (a) your own quirks no standard software knows about, (b) workflows common to your industry, (c) something custom enough that pre-built tools can't automate it.

How the system works

The 3 layers have distinct, non-overlapping roles:

  1. Supabase via MCP — it's your database. Lives in the cloud, accessible from the browser, free up to 500MB. Holds the data that's only yours (categorizations, deadlines, internal notes). Claude Code talks to it through the official Supabase MCP connector — an open protocol that lets Claude read and write directly to the DB, without you writing code.
  2. Claude for Small Business — the package Anthropic released on May 13, 2026, inside Claude Cowork. 15 ready-made workflows + 15 skills + 7 connectors (QuickBooks, PayPal, HubSpot, Canva, DocuSign, Google Workspace, Microsoft 365). It handles what every small business does.
  3. Agent View — the Claude Code dashboard that launches custom agents in parallel. You use it when the pre-built package doesn't cover something that's only yours, and you need to write it yourself (in markdown, not code).
Division rule between the 3: if it's custom data for your business → Supabase. If it's an operation common to all small businesses → Claude for Small Business. If it's a custom operation the pre-built package can't do → Agent View. Knowing this, you know where to put anything.

Step 1 — Supabase via MCP connector: your structured data

The first layer is your business database. Not your bank accounts (those stay at the bank), not your invoices (those stay in QuickBooks). It's your facts that no standard software knows about: how you categorize clients, which custom deadlines you track, the internal notes you share with the team.

What Supabase + MCP is: Supabase is a cloud service that gives you a ready-to-use PostgreSQL database, accessible from the browser, with a visual panel to create tables without writing SQL. MCP (Model Context Protocol) is an open protocol that lets Claude talk to external services: Supabase has an official MCP connector that, once installed, lets Claude read and write directly to the DB.

Why it beats Excel (5 concrete reasons)

AspectExcel / Google SheetsSupabase via MCP

In our case

We create 4 tables for the accounting firm's DB: clients (registry + tax regime + notes), tax_regimes (lookup table of regimes with their rules), custom_deadlines (firm-specific deadlines not in the standard fiscal calendar), internal_notes (team comments on each client). The schema is in materiali/schema-aziendale.sql: you open it in Supabase's SQL Editor, click Run, and it's created.

What to do

  1. Create the Supabase project
    Go to supabase.com, "New project", pick a region near you, set a DB password and save it.
  2. Load the business schema
    Panel "SQL Editor" → "New query" → paste the contents of materiali/schema-aziendale.sql → Run. 4 tables created + relations + indexes.
  3. Copy URL and Service Role Key
    Settings → API → copy Project URL and service_role key. They go in .env (never on camera — they give total access to the DB).
  4. Install the Supabase MCP connector
    claude mcp add supabase
    Prompts for URL and key (already copied). From that moment Claude Code has read-write access to the DB through MCP. Table schema, rows, queries — all visible.
  5. Verify
    claude > "Show me the tables in the Supabase DB and how many rows they have"
    📊 4 tables: clients (0), tax_regimes (5), custom_deadlines (0), internal_notes (0). MCP connector working.

Step 2 — Claude for Small Business: Anthropic's pre-built package

The second layer is an important new arrival that changes how a small business approaches AI. On May 13, 2026 — last week as of this video — Anthropic released Claude for Small Business, a package of workflows and skills already written for the common things every small business does. What used to cost you weeks of custom scripting is now a toggle.

What it is in practice: inside Claude Cowork (Anthropic's browser interface for teams) there's a plugin called "Small Business". You enable it with the command /smb-onboard and it walks you through a guided experience: it asks which business tools you already pay for, connects them with one click each, and after 10 minutes you have 15 ready workflows talking to QuickBooks, PayPal, HubSpot, Canva, DocuSign, Google Workspace, Microsoft 365.

What it contains (concretely)

The 15 workflows are slash commands you run inside Cowork. The most used:

CommandWhat it does
/monday-brief Monday morning summary: current cash (reads QuickBooks), invoices due, new CRM leads (reads HubSpot), suggested next action.
/close-month Monthly close: reconciliation between invoices issued, collected, paid to suppliers. Writes the "P&L narrative" — the natural-language comment on why the numbers are what they are.
/invoice-chaser Automatic reminders for overdue invoices. Writes the email personalized to the client and the relationship, but YOU approve BEFORE it sends. No blind automated sends.
/plan-payroll Monthly payroll planning: calculations, paystubs, contribution deadlines. Pulls from the payroll system you connected.
/run-campaign Marketing campaigns: drafts the copy, generates visuals with Canva, segments the list in HubSpot. You approve before publishing.
/contract-review Contract review: reads a PDF in DocuSign, highlights risky clauses, suggests changes.

The 15 skills are smaller building blocks that activate automatically inside the workflows: cash-flow forecasting, margin analysis, lead triage, customer sentiment, tax prep, hiring packet builder, and others.

The 4 guarantees that make it small-business-ready

  • Your permissions carry over: if a teammate can't see something in QuickBooks or Google Drive with their account, they can't see it through Claude either. No security holes created by AI.
  • Mandatory human approval before anything goes out: no email gets sent, no payment processed, no post published without your "OK".
  • Anthropic doesn't train on your business data on Team and Enterprise plans. Your numbers stay yours.
  • Cost: zero extra beyond the Claude Cowork Team plan you're paying anyway. It's a free plugin inside a plan you already have.

In our case

For the accounting firm, we enable the package and connect: QuickBooks (firm's client accounting), Google Workspace (shared Drive where clients upload invoices and receipts, Gmail to send monthly reports), DocuSign (mandate signing). The 3 workflows we use first: /monday-brief for the Monday check, /invoice-chaser for the firm's reminders to its own clients, /close-month for the monthly accounting close.

What to do

  1. Log into Claude Cowork
    Open claude.com/cowork, log in. Requires Team plan. If you have the single Pro plan you don't see Cowork — you need to upgrade to Team (~$25/user/month).
  2. Launch the package onboarding
    /smb-onboard
    Command to type into the Cowork chat. The guided procedure starts, asking which tools to connect.
  3. Connect your business tools
    Pick from the list: QuickBooks, Google Workspace, HubSpot, DocuSign, etc. Each connection is a click + OAuth login. You don't need Google Cloud Console, you don't need credentials.json: Anthropic has pre-registered the app, you just give consent.
  4. Try the first workflow
    /monday-brief

  5. Expand gradually
    Don't connect everything at once. Start with 2-3 tools you actually use daily (e.g. QuickBooks + Google Workspace). Add the others only when you realize you need them.

Step 3 — Agent View: custom agents in parallel

The pre-built package covers a lot, but not everything. The things that are yours — how you categorize clients, your industry's quirks, document types only you handle — you have to write those yourself. Fortunately "writing" here means writing a markdown file in plain language, not code.

What Agent View is: the Claude Code dashboard that lets you launch and manage multiple AI agents in parallel from the same screen. You open it with claude agents. Each agent is a markdown file in .claude/agents/ with a name, a description, the tools it can use, and instructions in plain English. They work simultaneously — one watches one thing, another watches something else — and you see all of them in the same dashboard.

In our case

For the accounting firm, we write 3 custom sub-agents that do things the Anthropic package can't do because they're too specific:

  • document-classifier: when a client uploads an ambiguous document (e.g. a "receipt" that could be a simplified invoice or a fiscal receipt), it classifies it by reading custom rules and updates Supabase.
  • regime-checker: weekly, checks if any client has crossed their tax regime threshold and logs an alert in Supabase's internal_notes table for the lead accountant.
  • deadline-alerter: every morning reads custom_deadlines from Supabase and prepares a list of the day's deadlines for each partner, to be delivered via Slack.

They all run in parallel from the same claude agents dashboard. You watch them work, interrupt them if needed, read their logs, decide when to fire a manual report.

Anatomy of a sub-agent (simple markdown)

--- name: regime-checker description: Checks tax regime thresholds for each client, writes alerts to Supabase tools: Read, Write, Bash, mcp__supabase --- # Instructions You are an agent that weekly checks the firm's clients' tax regimes. 1. Read the `clients` table on Supabase: for each client get `tax_regime_code` and `current_year_revenue`. 2. Compare against the regime limit (table `tax_regimes`): - Forfettario: limit €85,000 - Minimi: limit €30,000 - Ordinario: no limit 3. For each client that has exceeded 80% of the limit: - Insert a row in `internal_notes` with type "threshold_alert" and text "Client X at N% of the limit, consider regime switch" 4. Generate a final log: "checked N clients, M alerts generated".

What to do

  1. Verify the agents folder is present
    ls .claude/agents/
    document-classifier.md regime-checker.md deadline-alerter.md
  2. Customize the sub-agents
    Open the 3 markdown files with VS Code. Change the instructions to match your firm (regimes you use, your thresholds, where you want the alerts). It's markdown, it's plain English, it's readable by anyone.
  3. Open Agent View
    claude agents
    You see a dashboard with the 3 defined agents, each in "ready" state. Click one to launch it. More clicks to launch more in parallel.
  4. Launch document-classifier on ambiguous documents
    While it parses, also launch regime-checker. The 2 run in parallel. When they finish, read the logs from the dashboard.
  5. (Optional) Schedule the agents with Claude Routines
    If you want them to run on their own at fixed times (e.g. regime-checker every Monday at 8) — see docs/claude-routines-howto.md.

Ready-to-customize sub-agents: document-classifier.md, regime-checker.md, deadline-alerter.md

All together: how the 3 layers talk to each other

Now that each of the 3 layers is in place, let's see the full flow for the accounting firm. Here's the typical Monday morning AFTER the infrastructure is up:

09:00 — You open Claude Cowork and type `/monday-brief` → the package reads QuickBooks (cash, invoices) → and reads Supabase (clients flagged by regime-checker last week) → tells you: "cash $12k, 4 invoices due, and heads-up: 2 clients are close to the forfettario limit" 09:15 — You open Claude Code and run `claude agents` → see 3 dormant custom sub-agents → launch document-classifier on the PDFs clients uploaded over the weekend to shared Drive → it classifies them, writes to `documents` in Supabase → in parallel regime-checker rechecks the updated revenues and updates `internal_notes` 09:45 — Back to Cowork, type `/invoice-chaser` → the package reads unpaid invoices from QuickBooks → BUT before writing the email, it checks `internal_notes` in Supabase (via MCP, which works both in Code and in Cowork): if a client has notes like "rough patch, don't chase", it skips them → proposes 3 personalized emails → you approve, they go End of month — Run `/close-month` → the package does the standard close (QuickBooks + entries) → and reads `custom_deadlines` from Supabase to add firm-specific items to the report → final report generated and saved to Drive via the package's Google Workspace connector
The moment when it all holds together: Supabase is your source of truth for your business (the facts only you know), the Anthropic package is the engine for common workflows, Agent View is the engine for custom workflows. The bridge between the 3 is Supabase's MCP connector, which works the same inside Claude Code (for custom agents) and inside Claude Cowork (for the package). The 3 read and write the same DB. No silos.

The 3 golden rules to keep it from getting messy

  1. No business data only in the tools connected to the package. QuickBooks has the invoices, HubSpot has the leads — but your own notes, custom categorizations, specific alerts must live in Supabase. Otherwise if you change accounting software tomorrow you lose everything.
  2. No common operation hand-written in custom. If a package workflow already does a thing (e.g. monthly close, invoice chasing, briefing), DON'T re-write it as a custom sub-agent. The pre-built is almost always better than what you'd write, and Anthropic will maintain it over time. Custom is only for what the package does NOT cover.
  3. Human approval for things going out. Standard of the package, replicate it in your custom agents. Never give permissions to "send email to clients" without explicit approval for each send.

Beyond the accounting firm: where the same schema works

The "Supabase via MCP + Claude for Small Business + Agent View" architecture is industry-agnostic. The Supabase tables and the custom sub-agents change, but the 3 layers remain.

Law firm Supabase: contracts_under_review, custom_critical_clauses, litigation_parties. Package: /contract-review for standard review. Custom: sub-agent that recognizes country-specific clauses the generic package doesn't flag.
Small e-commerce (Shopify/WooCommerce) Supabase: suppliers, price_history, margins_by_category. Package: /margin-analyzer and /run-campaign for margins and promos. Custom: sub-agent that parses your specific suppliers' PDF price lists and updates prices in Supabase before running the package's analyses.
Communication agency Supabase: active_briefs, creative_team, brand_guidelines. Package: /run-campaign for campaigns, /monday-brief for weekly planning. Custom: sub-agent that reads brand guidelines from Supabase and checks that the creatives generated by the package respect them.
B&B or hospitality Supabase: bookings, returning_guest_preferences, tourist_tax_by_municipality. Package: /close-month for monthly close and /monday-brief for arrivals check. Custom: sub-agent that calculates tourist tax with your specific municipality's rates (which the generic package doesn't know).
Trades / workshop Supabase: active_jobs, timing_by_type, materials_consumed. Package: /plan-payroll for payroll and /invoice-chaser for payments. Custom: sub-agent that estimates a new job's time by comparing it with similar historical jobs in Supabase.
