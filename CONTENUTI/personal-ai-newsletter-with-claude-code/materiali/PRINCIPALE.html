What is a personal AI newsletter

A normal newsletter is written by one person, sent to thousands. Topics you often don't care about. Ads in the middle. Imposed frequency. Imposed tone.

A personal AI newsletter is written by Claude for you only. You choose the sources. You choose the frequency. You choose the tone. The filter is your brain (expressed in 5 lines of instructions), not any social network's algorithm.

The point: you turn the internet into an assistant that every morning brings only the things that matter to you onto your desk. No open browsers, no notifications, no FOMO.

System characteristics:

  • Local: runs on your PC with Claude Code, no cloud, no data upload
  • Private: nobody sees your sources or your summaries
  • Editable in 30 seconds: change sources by editing a JSON file
  • Schedulable: starts by itself every morning with Claude Routines
  • No duplicates: Claude remembers what it's already seen and won't show it to you again

What we'll build today

To demonstrate the pattern we'll use a simple, verifiable case: a daily newsletter on Anthropic's new releases (the company that makes Claude). Every morning at 8, Claude visits Anthropic's news page, identifies articles published in the last 24 hours, summarizes each in 3-5 bullets, and drops a clean markdown file on your desk.

Example of how a generated newsletter looks:

# 🧠 Your AI Brief — Friday May 16, 2026 ## 3 Anthropic updates today ### 🚀 Claude Sonnet 4.7 available in beta - 15% performance increase on reasoning tasks - New "thinking" model activatable on demand - Available immediately on API and Claude.ai - 🔗 anthropic.com/news/claude-sonnet-4-7 ### 📄 Paper: "Constitutional AI v2" - Update to the system of principles behind training - Focus on transparency of safety trade-offs - 🔗 anthropic.com/research/constitutional-ai-v2 ### 🔧 Claude Code: new "Plan Mode" feature - Mode that separates planning and execution - Useful for complex multi-step tasks - 🔗 anthropic.com/news/plan-mode --- Generated in 47 seconds · 3 articles read · 2 articles skipped (already seen)

You open the file, read in 90 seconds, you know as much as someone who spends 2 hours a day following the ecosystem. Done.

The example is "Anthropic news", but at the end of the video we'll see that the same pattern works for any site: competitors, industry blogs, academic papers, niche sources.

How the system works

Only 3 pieces, all text files you edit with VS Code:

📁 THE "NEWSLETTER" FOLDER (everything in here) ┌──────────────────────────────────────────────────────┐ │ │ │ 📝 sources.json → "read these sites" │ │ 📝 CLAUDE.md → "write in this tone" │ │ 📝 prompts/ → "here's exactly what to do" │ │ 📝 state.json → memory: what I've already seen │ │ │ │ 📂 newsletter/ │ │ └── 2026-05-16.md ← today's output │ │ │ └──────────────────────────────────────────────────────┘ │ ▼ 🤖 CLAUDE CODE (launches → visits sites → summarizes → saves file) │ ▼ ⏰ CLAUDE ROUTINES (at 8 every morning it starts it)

Claude Code already has all the tools needed:

  • Web fetch: opens a URL and reads its content. Built-in.
  • File write: writes the markdown file. Built-in.
  • State tracking: uses state.json to remember what it has already processed. Updates it by itself.
  • Routines: Claude Code's scheduling system. One line to tell it "do it at 8".

No Python, no third-party API keys, no databases. Just Claude and files.

Step 1 — Define the sources

The sources are the sites Claude visits every morning. In our case: the Anthropic pages where new things come out.

The sources.json file contains a list of URLs with a label. You edit it with VS Code. Add a source, remove one, in 10 seconds.

Example of ready-to-use sources.json

{ "sources": [ { "name": "Anthropic News", "url": "https://www.anthropic.com/news", "category": "product" }, { "name": "Anthropic Research", "url": "https://www.anthropic.com/research", "category": "research" }, { "name": "Claude Code Changelog", "url": "https://docs.claude.com/en/release-notes/claude-code", "category": "changelog" } ] }

3 starting sources. A news page (product announcements), a research page (papers), a changelog (release notes). Three pieces of the "Anthropic news" puzzle.

To add a source of yours (e.g. a blog you care about): add a block with name, url, category. No weird syntax, it's a list.

Ready file: materiali/sources.json.

Step 2 — Define the tone

A badly synthesized newsletter is worse than no newsletter. If Claude writes verbosely, academically, with paragraphs of 10 lines, you'll never read the file.

The CLAUDE.md file at the root of the folder tells Claude how to write. Tone, length, structure, what to emphasize. Claude reads it automatically at the start of every session.

Example of ready-to-use CLAUDE.md

## Newsletter tone - English, direct, colloquial - Max 3-5 bullets per article - Max 1 line per bullet - No generic intros/outros ("here are today's news…") - No marketing adjectives ("revolutionary", "incredible") - Always the original link at the end of each article ## What to emphasize - Concrete numbers (versions, percentages, prices) - What changes for those who use the product - Availability dates ## What to skip - Partnership announcements without concrete details - "Filler" articles (sponsored events, open positions) - Stuff already covered in previous runs (check state.json)

3 tone rules, 3 things to emphasize, 3 things to skip. It's a 20-line instruction sheet that applies to all future runs. You edit it once, it always applies.

Ready file: materiali/CLAUDE.md.

Step 3 — Launch the first run

Now you start Claude for the first time and see what it produces.

One single command. Open the terminal inside the materials folder, type claude, and give the prompt you find in prompts/newsletter-daily.md. Claude visits the sources, identifies new items, writes the newsletter, updates the state. ~1 minute.

What to do

  1. Open Claude Code in the folder
    cd materiali claude
  2. Give the prompt

    Copy the content of prompts/newsletter-daily.md and paste it. Or say:

    run the prompt in prompts/newsletter-daily.md
  3. Wait ~1 minute

    Claude tells you what it's doing step by step: which source it's reading, which articles it found, which it skipped because they were already seen. Transparent.

  4. Open the generated file

    Inside newsletter/ you find YYYY-MM-DD.md. You open it with VS Code or any markdown reader (e.g. Obsidian, Typora).

    📂 newsletter/ └── 2026-05-16.md ← here's your first newsletter

If you don't like the result, go back to Step 2 and change the tone in CLAUDE.md. Relaunch. You iterate in 30 seconds.

Orchestrator prompt: materiali/prompts/newsletter-daily.md. Output example: materiali/example-output.md.

Step 4 — Schedule with Claude Routines

It works, the first run is done. Now we want it to start by itself every morning, without you opening the terminal.

Claude Routines is Claude Code's built-in scheduling system. One line to say "every day at 8, start this prompt in this folder". No cron, no Windows Task Scheduler, no YAML files.

What to do

  1. Create the routine
    claude routines add daily-newsletter \ --schedule "0 8 * * *" \ --cwd "/path/to/materiali" \ --prompt "run prompts/newsletter-daily.md"

    Translation in plain English: "every day at 8:00, enter materiali and start the prompt".

  2. Verify
    claude routines list
    📋 Active routines: • daily-newsletter — every day at 08:00 — next: tomorrow 08:00
  3. Manual test (so you don't wait until tomorrow morning)
    claude routines run daily-newsletter

    Forces the execution now. If it works, from tomorrow it starts by itself.

From tomorrow morning, at 8 you'll always find a new file in newsletter/. You do nothing.

Alternative if you don't have Claude Routines: use Windows Task Scheduler or cron on Mac/Linux. The script to launch is one line: cd /path/to/materiali && claude --print "$(cat prompts/newsletter-daily.md)". Full example in materiali/scheduling/crontab-example.txt.

Complete scheduling guide: materiali/scheduling/claude-routines.md.

Step 5 — A team of specialized agents

The system works. Every morning the file arrives. But it always does the same thing: read sources, summarize. Period.

Now we make it smart. We add 2 small specialized agents that activate automatically when needed, without you having to think about it.

The idea: the main orchestrator does the standard job (fetch + summary). When it encounters special cases — a day without news, or a major update to flag — it automatically calls an agent specialized in that specific case. You only see the final result: a richer, more useful, more reliable newsletter.

The 2 agents

🚑 empty-day-rescue Activates when the orchestrator finishes the run with zero new articles in the last 48 hours. Instead of leaving you an empty file, it goes to secondary sources defined separately (official Anthropic tweets, AI podcasts, founder blogs you flagged) and pulls 1-2 deep-dive contents — even if they're not strictly "news". Result: zero empty days.
🚨 major-update-spotter Activates ALWAYS at the end of the run, on the just-produced results. It classifies each article by importance and if it finds a major update — a new model released, a new product/tool/service, an important breaking change — it highlights it at the top of the file with a red 🚨 MAJOR UPDATE box and suggests 1-2 concrete actions (e.g. "try the model on Claude.ai", "read the announcement post"). Result: the news that matters doesn't get lost among the minor ones.

How the team works

🤖 ORCHESTRATOR (prompts/newsletter-daily.md) │ "read sources, summarize news" │ ├──── 0 results? ─── YES ──▶ 🚑 empty-day-rescue │ (searches secondary sources) │ ▼ 📄 newsletter/YYYY-MM-DD.md │ ▼ 🚨 major-update-spotter (re-reads the file, puts major updates on top) │ ▼ 📄 newsletter/YYYY-MM-DD.md ← enriched

The agents live as text files in .claude/agents/. Claude Code recognizes them automatically — you don't have to configure anything else.

What to do

  1. The 2 agent files

    They're already in the materials, in .claude/agents/empty-day-rescue.md and .claude/agents/major-update-spotter.md. They're Markdown files with a small YAML header that tells Claude Code: "this is a sub-agent, called X, does Y, can use these tools".

    --- name: empty-day-rescue description: Activates when the daily newsletter is empty. Searches deep-dive content on secondary sources. tools: [web_fetch, file_write] --- You are a "rescue" agent for the daily newsletter. When the orchestrator calls you, it has 0 new articles in the primary sources. Go to the sources listed in `sources-fallback.json` and ... [full rules inside the file]
  2. The secondary sources list

    The empty-day-rescue agent needs to know WHERE to go when primary sources are empty. The sources-fallback.json file contains this list — already prepared with 3 examples (Anthropic on X, Dario Amodei's blog, Latent Space podcast). You edit it with VS Code if you want to change the backup sources.

  3. The updated orchestrator

    The prompts/newsletter-daily.md file now includes 2 new lines at the end: "if I found 0 articles, call empty-day-rescue. In any case, at the end, call major-update-spotter on the just-saved file." No code, they're instructions in English. Claude Code interprets and delegates.

  4. Test

    Relaunch the prompt as you did in Step 3:

    claude --print "$(cat prompts/newsletter-daily.md)"

    You see that now Claude, in its steps, says things like "calling major-update-spotter…" and in the output file you find (if there really is a major update today) a box at the top like this:

    ## 🚨 MAJOR UPDATE — Claude Sonnet 4.7 available in beta > New model with +15% reasoning performance. Available now on API and Claude.ai. > **What to do**: try it on claude.ai/new and compare with 4.6 on your most demanding recurring task. --- [then the normal newsletter follows...]

When this system really makes a difference

  • On weekends and holidays: Anthropic and other companies publish little. Without empty-day-rescue you'd have empty files, you'd forget about the system. With it, you always have something to read.
  • On major releases: without major-update-spotter, an important launch can end up buried among 5 minor articles and you miss it. With it, it's the first thing you see when you open the file.
  • To scale the system: tomorrow you want to add a third agent (e.g. "translator", "code extractor", "fact-checker")? You create a new file in .claude/agents/ with its description, tell the orchestrator when to call it, done. The pattern extends infinitely.
Sub-agent vs single big prompt: you could have put all this logic inside the main orchestrator (a single mega-prompt that does fetch + summary + fallback + classification + spotting). It would work, but it would become unmanageable fast. Splitting into specialized sub-agents has 3 advantages: 1) clarity (each file does one thing only), 2) reusability (the major-update-spotter tomorrow you reuse on another newsletter, just copy a file), 3) debugging (if something doesn't work, you know exactly which agent to touch).

Agent files: materiali/.claude/agents/empty-day-rescue.md · materiali/.claude/agents/major-update-spotter.md. Fallback sources: materiali/sources-fallback.json.

Beyond Anthropic: how to apply the pattern

The "Anthropic news" example is one of a thousand ways this system combines. You change 2 files (sources.json and CLAUDE.md), and Claude works for another case. Same folder, same prompt, same scheduling.

Competitor newsletter In sources.json you put the sites of your 3 competitors (blog pages, news, changelogs). In CLAUDE.md you say "emphasize prices, product launches, strategic moves". Every morning you know what they're doing without opening LinkedIn.
B2B industry newsletter Sources: 5-10 blogs/publications in your industry (e.g. fintech: Sifted, Finextra, EU-Startups; legal: Legalweek, Above the Law). Tone: "technical language, English, emphasis on deals and regulation". 10 minutes of reading replaces 2 hours of scrolling.
Academic paper newsletter Sources: selected arXiv categories (e.g. cs.AI, cs.CL), Google Scholar Alerts. Tone: "explain accessibly, include links to PDF papers". You keep up with research without having to read cryptic abstracts.
Social trend newsletter (consultants, agencies) Sources: LinkedIn accounts of top voices in your industry (via public pages). Tone: "extract strong opinions from the last week, max 3 per person". You understand what your professional world is talking about without living on LinkedIn.
"Clipping" newsletter for PR / brand monitoring Sources: publications that might mention your brand. In CLAUDE.md: "skip everything, only report articles containing the word 'XXX' (my brand) or 'YYY' (my products)". Brand monitoring done in-house, free, every morning.

The pattern: sources + tone + state tracking + scheduling. Only what you put in sources.json and CLAUDE.md changes. The rest is identical.
