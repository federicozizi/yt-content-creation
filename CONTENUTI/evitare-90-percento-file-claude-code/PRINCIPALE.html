Le 5 tecniche per evitare il 90% dei file che Claude Code genera (e non ti servono)

Guida regista - per la registrazione. Non e' un documento pubblico.
Intro - sotto 1 minuto

Apertura — la scena che riconosci

Cosa mostrare a schermo

Schermo registrato: una cartella VS Code con file in vista. Mostra una **vera cartella sporca**: 25-30 file alla rinfusa, mix di file utili (src/, README.md) e cartacce inutili (TEST_, NOTES_, SCRATCH_, summary_, debug_). Mentre la mostri, gli occhi tuoi scorrono i file e scrolli un attimo. Poi torna CAMERA su di te per la voce.

Cosa dire (verbatim)

"Questa e' la cartella di un mio progetto, dopo due settimane di lavoro con Claude Code. Guarda. Ho chiesto a Claude semplici cose — aggiungi un campo qua, sistema un bug la' — e a fine giornata mi trovo trenta file nuovi. Test che non ho chiesto, sommari di sommari, note di debug, scratch dei suoi ragionamenti. Ne usero' tre, gli altri ventisette sono rumore."

"Se hai mai aperto un progetto e ti sei detto 'ma cosa sono tutti questi file', sei nel posto giusto. In questo video ti mostro cinque tecniche concrete per riprendere il controllo. Applicate insieme, eliminano circa il novanta percento dei file inutili. Vado dalla piu' semplice — dieci minuti di lavoro — alla piu' tecnica, in modo che tu fermi al livello che ti basta."

"Tutti i file di configurazione che uso — CLAUDE.md, settings.json, prompt-tipo — li scarichi gratis nel link in descrizione. Iniziamo."

Test della voce: leggilo in 55-65 secondi. Il momento clou e' "ne usero' tre, gli altri ventisette sono rumore" — quella frase fa annuire l'audience riconoscente. Non saltarla.
STEP 1

Perche' Claude lo fa — capire la causa prima della cura

Cosa mostrare a schermo

Lavagna o slide. Disegna tre frecce dall'utente ("io chiedo: aggiungi campo email") verso Claude, e poi tre frecce di Claude che producono:

  • Codice modificato (giusto, lo volevo)
  • TEST_email_validation.md (non chiesto)
  • summary_changes.md (non chiesto)
  • NOTES_2026-05-22.md (non chiesto)

Sotto, evidenzia "Tu vedi 4 cose, ne volevi 1".

Cosa dire (verbatim)

"Prima di darti le cinque tecniche, vale la pena spiegare velocemente perche' Claude si comporta cosi'. Non e' un bug: e' una scelta di training. Anthropic ha addestrato il modello con l'incoraggiamento a 'mostrare il proprio lavoro' — generare test, scrivere sommari, lasciare tracce dei propri ragionamenti. L'idea era: aiutare il developer a capire cosa il modello ha fatto."

"Per chi e' developer esperto, e' a volte utile. Per chi non e' developer, e' rumore. Tu vedi sette file dove ne volevi due. Cliffhanger psicologico: quale di questi e' importante? E magari ne cancelli uno utile per sbaglio. O semplicemente la cartella diventa illeggibile."

"La buona notizia: tutto questo comportamento si DISCIPLINA. Claude e' istruibile. Cinque tecniche da combinare, ognuna agisce a un livello diverso. Andiamo a vederle."

STEP 2 — TECNICA 1

CLAUDE.md con sezione "Output Discipline"

Cosa mostrare a schermo

Apri VS Code sul tuo progetto. Mostra:

  • Il file CLAUDE.md aperto (se non esiste, lo crei)
  • Aggiungi alla fine la sezione "Output Discipline" — incolla dall'esempio dei materiali, scrolla per mostrare la lista dei pattern banditi (TEST_*, NOTES_*, SCRATCH_*, ecc.)
  • Salva. Riavvi Claude Code.
  • Nuovo task piccolo: "aggiungi commento in cima al file index.js". Verifica che Claude esegua e NON crei file extra.
Cosa dire (verbatim)

"Tecnica numero uno, la piu' semplice e la piu' importante: aggiungere una sezione di disciplina output al CLAUDE.md del tuo progetto."

"Il CLAUDE.md, te lo ricordo se sei nuovo, e' un file che Claude legge per primo ad ogni sessione. E' la 'costituzione' del progetto. Funziona MOLTO bene se ben scritto — Claude lo rispetta per default."

"Aggiungo una sezione che si chiama 'Output Discipline' con tre cose. Prima cosa: lista esplicita di pattern di file che NON deve mai creare — TEST con underscore tutto maiuscolo, NOTES, SCRATCH, debug con underscore, summary con underscore. Seconda cosa: regola sui sommari — non creare mai sommari come file, dimmeli a voce nella chat. Terza cosa: regola sui ragionamenti — se hai bisogno di pensare stati intermedi, usa il thinking interno, non file scratch su disco."

"Salvo. Riavvio una nuova sessione di Claude Code per essere sicuro che ricarichi il file. Test piccolo: 'aggiungi un commento in cima al file index.js'. Boom, Claude esegue, modifica un solo file, niente extra. Tecnica uno applicata in dieci minuti, blocca circa il sessanta percento dei file inutili. Buon inizio."

STEP 3 — TECNICA 2

Deny patterns nel settings.json

Cosa mostrare a schermo

Sequenza:

  • Apri .claude/settings.json del progetto (o lo crei). Mostra la sezione "permissions"
  • Aggiungi sezione "deny" coi pattern del file esempio-settings.json dei materiali
  • Salva
  • Test: chiedi a Claude esplicitamente "crea un file NOTES_test.md". Mostra l'errore "Permission denied" — la regola funziona.
Cosa dire (verbatim)

"Tecnica numero due: deny patterns nel settings.json. Questa funziona a un livello completamente diverso dalla prima — non sta nel prompt, sta nel sistema. Claude PUO' tentare di scrivere un file vietato, ma il tool Write fallisce con 'Permission denied' e lui se ne accorge."

"Aggiungo al file settings.json del progetto una sezione 'permissions' con 'deny' e dentro la lista di pattern, scritta in formato glob — quindi con asterischi. Tipo Write tra parentesi due asterischi slash TEST underscore asterisco. Tradotto: 'in qualsiasi sottocartella, nessun file il cui nome inizia con TEST underscore'."

"La cosa potente di questa tecnica: bypassa il problema della 'dimenticanza' della tecnica uno. Anche se Claude, in una sessione lunga, dimentica per un momento le regole del CLAUDE.md e tenta di scrivere un file TEST underscore, il sistema lo blocca prima."

"Verifico: chiedo esplicitamente a Claude 'crea un file NOTES underscore test punto md'. Lo prova. Tool Write torna errore 'Permission denied'. Claude se ne accorge, mi dice 'non posso creare quel file perche' e' bloccato dalle tue permissions'. Funziona. Tecnica due applicata in cinque minuti."

STEP 4 — TECNICA 3

Hook PreToolUse Write — il guardiano attivo

Cosa mostrare a schermo

Stessa schermata settings.json. Mostra l'aggiunta della sezione "hooks":

  • Sezione hooks.PreToolUse.matcher = "Write"
  • Hook che chiama uno script Node esterno (es. ~/.claude/check-write-discipline.js)
  • Apri lo script in VS Code, mostra la logica: legge il filename, blocca se pattern vietato
  • Test: chiedi a Claude "crea un file di ragionamento sui prossimi step". Mostra che Claude prova, hook lo blocca, e Claude desiste senza creare niente.

NB: lo script check-write-discipline.js non e' nei materiali (e' nel video, gist GitHub linkato). Per il regista: tieni il gist pronto durante la registrazione.

Cosa dire (verbatim)

"Tecnica numero tre — questa e' la piu' tecnica delle cinque, ma anche la piu' potente per chi vuole il massimo controllo. Si chiama hook PreToolUse Write."

"In sintesi: un hook e' un piccolo script che Claude Code chiama PRIMA di eseguire un certo tool. Nel nostro caso, prima di ogni Write. Lo script puo' guardare cosa Claude sta per scrivere — nome file, contenuto — e decidere se lasciarlo passare o bloccarlo."

"Apro il file ~/.claude/check-write-discipline.js. E' uno script Node piccolo, una trentina di righe. La logica: prende il filename dalla richiesta di Write, controlla se matcha i pattern banditi che ho elencato, e se matcha stampa 'BLOCKED' e ritorna un exit code di errore. Claude vede l'errore e desiste."

"Test: chiedo a Claude 'scrivi un file di ragionamento sui prossimi tre step del progetto'. Claude prova a creare 'ragionamento underscore prossimi step punto md'. L'hook intercetta, controlla, BLOCK. Claude torna nel suo thinking e mi spiega cosa pensa direttamente nella chat. Esattamente quello che volevo."

"Lo script completo lo trovi in un gist GitHub linkato nei materiali — quindici minuti di setup, controllo massimo per sempre."

STEP 5 — TECNICA 4

Skill personalizzata "Output minimalista" — la versione portatile

Cosa mostrare a schermo

Mostra:

  • Apri terminale: mkdir -p ~/.claude/skills/output-minimalista
  • code ~/.claude/skills/output-minimalista/SKILL.md
  • Mostra il contenuto del file con frontmatter (name, description) e regole
  • Salva. La skill ora e' a livello utente — vale per TUTTI i tuoi progetti
  • Test rapido su un secondo progetto diverso: verifica che la skill si attivi automaticamente quando Claude rileva opportunita'
Cosa dire (verbatim)

"Tecnica numero quattro — la versione portatile delle prime tre. Se le tecniche uno, due, tre vanno bene per UN progetto specifico, la skill personalizzata e' la stessa idea ma a livello del tuo USER profile, quindi vale per tutti i progetti."

"Cos'e' una skill, breve riassunto. Le Claude Skills sono pacchetti di expertise che Claude carica automaticamente quando riconosce che servono. Sono nate per cose grosse — tipo 'gestione PDF' o 'pacchetto di workflow business'. Ma puoi crearne di tue, semplici, per i tuoi scopi."

"Creo la cartella tilde slash punto claude slash skills slash output trattino minimalista. Dentro creo un file SKILL.md con un frontmatter — nome della skill, description — e poi le regole, le stesse che gia' conosci ma in forma di skill."

"Vantaggio rispetto a CLAUDE.md: questa la porto su tutti i miei progetti senza dover ripetere la sezione output discipline ovunque. Vantaggio rispetto a settings.json: piu' espressiva, posso scrivere logiche piu' sfumate in linguaggio naturale."

"Svantaggio: meno deterministica. Le skill 'si attivano quando Claude pensa che servano'. Funzionano bene il novanta percento delle volte, ma se vuoi blindare al cento percento, abbinala alle tecniche uno e due. Sinergia, non sostituzione."

STEP 6 — TECNICA 5

Prompt iniziale rinforzato — il richiamo che funziona sempre

Cosa mostrare a schermo

Mostra:

  • Apri Claude Code, inizia una nuova sessione
  • Come primo messaggio incolla il blocco "Output Discipline regole di sessione" preso dal file prompt-tipo.md dei materiali
  • Sotto il blocco, scrivi la tua richiesta vera
  • Mostra che Claude conferma le regole e poi esegue il task pulito
  • Sotto, in basso, mostra un overlay: "DISCIPLINE keyword per richiamo veloce in sessione lunga"
Cosa dire (verbatim)

"Tecnica numero cinque, l'ultima — il prompt iniziale rinforzato. E' la cima dello stack. La metti SOPRA tutto il resto."

"Idea semplice: ogni volta che inizi una sessione importante, il PRIMO messaggio che mandi non e' la tua richiesta — e' un blocco di reminder delle regole di output discipline. Tre paragrafi, copia-incolla, ci metti dieci secondi."

"Cosa contiene il blocco. Riassunto delle regole — niente file scratch, niente notes, niente debug. Eccezioni esplicite — 'se ti chiedo crea il file X, fallo'. E una keyword di richiamo che io uso, si chiama 'DISCIPLINE'. Se durante la sessione vedo che Claude sta tornando alle vecchie abitudini, gli mando in chat solo la parola 'DISCIPLINE' e lui ricarica le regole."

"Funziona molto bene su sessioni LUNGHE. Quando Claude lavora per un'ora di seguito su un task complesso, a volte la pressione del task lo fa 'dimenticare' delle regole del CLAUDE.md. La parola di richiamo lo riporta in carreggiata in due secondi."

"Il blocco completo, incluso il prompt-tipo, lo trovi nei materiali in descrizione. Lo salvo come snippet nel mio VS Code — lo lancio in due tasti."

STEP 7

Lo stack finale + il prima e dopo

Cosa mostrare a schermo

Schermo split verticale:

  • Sinistra: PRIMA — la cartella con i 32 file di cui 25 inutili (la stessa dell'intro)
  • Destra: DOPO — la stessa cartella dopo 2 settimane di lavoro con tutte e 5 le tecniche attive, 8 file totali, tutti utili

Sotto, una piccola riga di consigli su quale livello dello stack applicare in base al tuo profilo:

  • Solo Tecnica 1 + 2 -> "Voglio risolvere il 70%, in 15 minuti"
  • Tecniche 1+2+5 -> "80%, 20 minuti"
  • Tecniche 1+2+3+5 -> "90%, 30 minuti (livello del video)"
  • Tutte e 5 + skill cross-project -> "95%, 45 minuti, copre tutti i progetti futuri"
Cosa dire (verbatim)

"Ricapitolando: le cinque tecniche lavorano in stack. Piu' ne applichi, piu' Claude sta nei binari. Te le ridico in ordine di setup time."

"Se vuoi il minimo sforzo per il massimo effetto: tecniche uno e due — il CLAUDE.md con la sezione di output discipline e il settings.json con i deny patterns. Quindici minuti totali. Risolvi circa il settanta percento del problema."

"Se vuoi salire ancora: aggiungi la tecnica cinque, il prompt iniziale rinforzato. Altri cinque minuti di setup, e ogni volta che inizi una sessione importante incolli il blocco. Ottanta percento risolto."

"Se vuoi blindare al massimo: aggiungi anche la tecnica tre, l'hook PreToolUse Write. Quindici minuti extra di setup tecnico, novanta percento risolto. Questo e' il livello che uso io e che ti faccio vedere nel prima-dopo."

"E poi c'e' la tecnica quattro, la skill personalizzata, che ti porta tutto il pacchetto su OGNI progetto futuro senza dover ripetere il setup. Quella la fai una sola volta nella vita."

"Risultato finale: dalla cartella sporca con trentadue file di cui venticinque inutili — vedi qui a sinistra — alla cartella pulita con otto file tutti utili che vedi a destra. Stesso progetto, stesso flusso di lavoro, dopo due settimane con le tecniche attive."
