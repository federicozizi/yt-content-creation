Before you start: install Claude Code

You only need Claude Code on a Pro plan ($20/month) or Max plan ($100/month). Nothing else.

For Agent View you need the CLI, not the Desktop app. Agent View is a full-screen dashboard that takes over the terminal: keyboard shortcuts, rows updating in real time, panels opening and closing. All of this only really works inside a real terminal (PowerShell, Windows Terminal, macOS Terminal, iTerm). The Desktop app is designed for regular chats, not TUI interfaces like this one.

The good news is that installing the CLI is a 2-minute, one-time job. After that, you just type claude from any folder and it runs.

Install in 3 steps

  1. Install Node.js from nodejs.org (LTS version, check "Add to PATH" during install). Verify with:
    node --version

    You should see a number ≥ 18.

  2. Install Claude Code via npm:
    npm install -g @anthropic-ai/claude-code
  3. Log into your account:
    claude

    The first time you run it, your browser opens for login. Sign in with your Anthropic account (the one with the Pro/Max plan).

Verify

Agent View requires version 2.1.139 or later. If you're on an older version:

claude update
How much does it use? Background sessions use the same quota as regular sessions. 4 in parallel = ~4x the consumption. The Pro plan handles sprints of 4-5 agents comfortably.

Step 1 — What Agent View is and how to open it

Agent View is a dashboard where you launch, supervise, and manage multiple Claude agents in parallel. Instead of working in one session at a time, you launch as many as you want and control them all from one screen.

Let's open it:

claude agents

A full-terminal screen opens. At the top you see the model in use and the current directory. In the middle is the sessions table (empty for now). At the bottom, the input where you'll type your tasks.

Claude Code v2.1.140 · claude-sonnet-4-6 · ~/project No sessions yet. Type a prompt below to dispatch your first agent. > _
Where are you? The directory at the top is the one you launched claude agents from. The agents you dispatch will work inside it. For our test, run the command from an empty working folder (e.g., create a folder named test-agent-view and run claude agents from there).
From this moment on, every prompt you type below dispatches an independent agent. This is not a chat: it's a dispatcher. Write what you want, hit Enter, and an agent goes off to work on it alone.

To leave Agent View: press Esc. The sessions you launched keep working even after you close it.

Step 2 — Launch the first agent

Let's start with something ambitious. Today we're building an interactive 3D globe of Earth, navigable in the browser, with real data for every country. And we're doing it with 4 agents in parallel.

First, let's create the project folder. Type into the Agent View input:

create a folder "interactive-globe" and inside it build a 3D globe of Earth with Three.js: rotation and zoom with the mouse, visible country borders, dark space background

Press Enter. Two things happen:

  1. A row appears in the table with status Working and an animated icon
  2. The agent starts creating files, installing dependencies, writing code — all on its own
Working ✽ 3d-globe Creating project structure... 0m > _

You don't have to do anything. The agent works, you watch the row update.

Step 3 — Launch 3 more agents in parallel

While the first agent works on the globe, let's launch 3 more. Each does something different, all working at the same time.

Type and Enter, one after the other:

in the "interactive-globe" folder, create a countries-data.json file with data for every country in the world: name, capital, population, GDP, continent, flag emoji
in the "interactive-globe" folder, create a sidebar panel in HTML/CSS: when you click on a country in the 3D globe, the panel shows its card with all the data from the JSON. Smooth opening animation
in the "interactive-globe" folder, build a landing page index.html that contains the globe, the data panel, an "Explore the World" title, a country search bar, responsive layout, elegant dark mode

The dashboard now shows 4 rows. Four agents working at the same time:

Working ✽ 3d-globe Building Three.js scene with country meshes 3m ✽ country-data Fetching country data, 120/195 done... 2m ✽ data-panel Creating sidebar component with animations 1m ✽ landing-page Writing index.html with responsive layout 0m > _
Here's the point: 4 agents working at the same moment. Each in its own isolated workspace (separate git worktree), without stepping on each other. You supervise from here.

Step 4 — Reading the dashboard

After a few minutes, the dashboard reorganizes itself. Sessions are grouped by status: first the ones that need you, then the ones working, then the ones that finished.

Needs input ✻ data-panel needs input: dark theme or light theme? 4m Working ✽ 3d-globe Adding country hover effects and labels 5m Completed ✻ country-data result: 195 countries saved to JSON 3m ✻ landing-page result: index.html with hero section done 6m

Everything you need is on this screen:

  • Animated icon ✽ = the agent is actively working
  • Yellow icon ✻ = the agent is asking you a question
  • Green icon ✻ = it finished successfully
  • Red icon ✻ = something went wrong

The summary on each row updates automatically every 15 seconds. You don't need to open any session to know where it stands.

Step 5 — Peek and Reply: answer without leaving

The "data-panel" agent needs an answer. Instead of entering the session, we use the peek: a quick panel that shows the question and lets you reply without leaving the dashboard.

Select the "data-panel" row with the arrow keys ↑↓, then press Space:

┌─ data-panel ──────────────────────────────────┐ │ │ │ The globe uses a dark space background. │ │ Should the country info panel match? │ │ │ │ 1. Dark theme (matches the globe) │ │ 2. Light theme (contrast, easier to read) │ │ │ │ [1] [2] │ │ │ │ > _ │ └────────────────────────────────────────────────┘

Press 1 to choose dark theme. The agent picks up again right away, you stay on the dashboard.

Other things you can do from the peek

  • ↑ / ↓ — scroll between sessions without closing the panel
  • Tab — auto-complete with a suggested reply, edit it, then Enter
  • Type something custom — e.g. "dark theme but with blue borders"
  • Prefix ! — send a shell command instead of a message

Step 6 — Attach and Detach: dive into a session

Sometimes peek isn't enough and you want the full conversation. Select a row and press Enter (or →):

The dashboard disappears and you find yourself inside the session, exactly as if you had opened Claude Code normally. Claude gives you a brief recap of what it did while you were away.

From here you can do everything: give instructions, correct, ask for changes, run commands. It's a full Claude Code session.

To return to the dashboard

Press ← on an empty prompt. You go back to the table, the session keeps working in the background.

Detaching never stops the session. ←, Ctrl+C, Ctrl+D, /exit: all of them take you back to the dashboard but the agent keeps going. The only way to really stop it is /stop.
Shortcut: Alt+1 through Alt+9 attaches directly to session 1-9 without selecting it first.

Step 7 — Organizing the dashboard

With many sessions the list gets long. Here's how to keep it clean:

ShortcutWhat it does
Ctrl+TPin a session to the top — you'll always find it first
Ctrl+RRename a session — useful when the auto-generated name isn't clear
Ctrl+SChange grouping — toggle between "by status" and "by folder"
Shift+↑ / Shift+↓Reorder sessions within a group
Ctrl+XStop a session — press it twice in 2 seconds to delete it
?Show all available shortcuts

Filter to find instantly

Type into the input without pressing Enter and the list filters in real time:

  • s:working — only active sessions
  • s:blocked — only the ones that need you
  • a:agent-name — sessions from a specific sub-agent
  • #123 or a PR URL — the session working on that pull request
Heads up: when you delete a session (double Ctrl+X), its worktree is wiped along with any unsaved code. Commit or push before deleting.

Step 8 — Moving sessions in and out of Agent View

Agent View isn't a closed world. You can move sessions in both directions.

From a regular session → into Agent View

You're working in a classic Claude Code session and want to move it to the dashboard? Type:

/bg

The session becomes a row in Agent View. You can also give it one last instruction before moving it:

/bg finish the refactoring and then commit

From Agent View → regular session

Attach the session (Enter), then work normally. When you're done, ← puts it back on the dashboard.

Launch directly from the terminal

You're not in Agent View but you want to launch a background agent:

claude --bg "create a README.md file for the interactive-globe project"
backgrounded · 7c5dcf5d

The session starts immediately and you'll find it on the dashboard the next time you open claude agents.

Step 9 — The final result

At this point the dashboard should show all agents completed:

Completed ✻ 3d-globe result: 3D globe with country borders ready 12m ✻ country-data result: 195 countries in JSON 3m ✻ data-panel result: dark sidebar with smooth animations 8m ✻ landing-page result: responsive page with search bar 10m

Four agents, all green. They worked at the same time: the total time is that of the slowest agent (~12 minutes), not the sum of all (~33 minutes).

Open the interactive-globe folder and launch index.html in your browser. You have a navigable 3D globe with real data for every country — built in 12 minutes by 4 agents that didn't even know about each other.

The point isn't the globe. The point is that you managed 4 AI workers from a single screen, answered their questions, checked the results, and got in 12 minutes what normally takes an hour. This works with any project.

Beyond the demo: where to use Agent View

The 3D globe was the demonstration. Agent View works anywhere you have independent tasks an AI can do without constant supervision.

  • Parallel content creation — One agent writes the article, one prepares the social posts, one creates the emails. You supervise from the dashboard, collect everything by end of morning.
  • Multi-source research — One agent analyzes competitors, one gathers pricing data, one monitors social media. Each works its own source, you collect the brief.
  • Multi-project — Open Agent View from the folder containing all your projects. Launch tasks in different repos with @repo-name. One dashboard for everything.
  • Development sprint — 5 sessions on different modules: fix, feature, test, docs, review. The isolated worktrees prevent conflicts.
  • Release preparation — One agent does the review, one runs the tests, one updates the docs, one prepares the release notes. Half a day compressed into 15 minutes.

The pattern is always the same: identify the independent tasks, launch them, supervise, collect.

Recap

  • claude agents opens the dashboard — from there you launch, supervise, manage
  • Every prompt in the input launches an independent agent that works on its own
  • Space for peek and quick replies, Enter to enter the session
  • ← to go back to the dashboard without stopping the agent
  • /bg to move an existing session into Agent View
  • claude --bg "prompt" to launch from the terminal without opening the dashboard
  • Sessions keep going even when you close Agent View
