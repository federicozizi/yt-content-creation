STEP 4

Quando le cose si rompono — le tre volte che ho sbattuto la testa

Cosa mostrare a schermo

Tre "scenette" in sequenza, ognuna con un'icona-tag colorata rossa "PROBLEMA 1", "PROBLEMA 2", "PROBLEMA 3":

  • Problema 1 — selettori CSS rotti: mostra il sito del competitor che cambia improvvisamente layout, vecchio selettore .price-now non trova piu' niente, il report email arriva con "60 prodotti scansionati, 0 prezzi estratti"
  • Problema 2 — banning IP: il competitor numero tre ha rilevato il pattern di scraping e ha bloccato l'IP del VPS. Errori HTTP 403 per ogni richiesta
  • Problema 3 — consumo API esploso: una notte Claude entra in loop perche' il sito risponde lento, riprova all'infinito. Al mattino, alert di budget all'80% in un giorno solo
Cosa dire (verbatim)

"Giorno sei, mattina, apro la mail. Report dello scraping notturno: 'sessanta prodotti scansionati, zero prezzi estratti'. Tutti gli scraping falliti. Vado a vedere: il competitor numero uno aveva cambiato il layout del sito nella notte. Il mio selettore CSS — la regola che diceva 'il prezzo sta in questo elemento HTML' — non trovava piu' niente. Vecchio problema dello scraping, lo conoscevo. Mi e' costato un'ora di riadattamento dei selettori. Bene, lezione imparata, primo problema risolto."

"Giorno diciassette: il competitor numero tre ha rilevato lo schema delle mie visite — sempre alle quattro di notte, sempre dallo stesso IP del VPS — e mi ha bannato. Errore HTTP quattrocento-tre per tutte le pagine. Lo scraping di quel sito era morto. Soluzione: ho dovuto introdurre un proxy che fa rotation degli IP, costo aggiuntivo dieci dollari al mese. Andiamo avanti."

"Giorno ventiquattro: il problema piu' grosso. Sveglia alle sette del mattino, controllo la mail. Notification da Anthropic: 'hai raggiunto l'ottanta percento del tuo budget mensile in un giorno solo'. Vado nei log. Una notte, il competitor numero uno aveva il sito stranamente lento, le risposte tornavano in trenta secondi invece di due. Claude ha ritentato, e ritentato, e ritentato. Loop infinito per ore. Bruciato cento dollari di token in una notte."

"Ed e' qui che e' nata la regola numero cinque, quella che oggi applico SEMPRE: budget limit hard nella console Anthropic. Anche col peggior bug possibile, il danno e' contenuto. Vediamo subito tutte e cinque le regole insieme."

STEP 5

Le 5 regole che ora applico SEMPRE

Cosa mostrare a schermo

Schermo a tutto schermo, le 5 regole come card numerate. Mentre parli di ognuna, evidenzia la card corrispondente. Sotto ogni card, una mini-icona del file che la implementa (es. settings.json icon, console anthropic icon).

  • Regola 1 — Mai eseguire come root
  • Regola 2 — Hook bloccanti per comandi distruttivi
  • Regola 3 — Logging aggressivo sempre
  • Regola 4 — Dry-run prima di ogni deploy
  • Regola 5 — Budget API con alert e hard limit
Cosa dire (verbatim)

"Regola uno: mai eseguire Claude Code come utente root sul VPS. Crea un utente dedicato con permessi minimi. Se Claude un giorno combina un casino — non per cattiveria ma per un prompt scritto male — il danno e' contenuto. Se invece gira come root, un comando sbagliato e' catastrofe. Mi e' successa una volta: Claude ha provato a fare un rm trattino rf su una cartella perche' aveva interpretato male un'istruzione del prompt. L'utente claude non aveva permessi, sistema operativo ha rifiutato, salvati. Se fosse stato root, era finita."

"Regola due: hook bloccanti per i comandi distruttivi. Nel file settings.json del VPS, aggiungo un hook PreToolUse che intercetta ogni chiamata al tool Bash e blocca a priori i comandi pericolosi — rm trattino rf, sudo, dd, mkfs. Anche se Claude dovesse provarli, l'hook li blocca. Ridondanza al di sopra dei permessi del sistema operativo. Il file completo, settings.json di produzione, e' nei materiali."

"Regola tre: logging aggressivo, sempre. Ogni esecuzione, Claude scrive un log dettagliato su slash var slash log slash claude trattino scraper punto log. Timestamp di inizio, decisioni prese, comandi eseguiti, timestamp di fine. Quando qualcosa va storto al mattino, ho la storia di cosa e' successo. Quando va tutto bene, ho metriche per ottimizzare il prompt. Senza log, sei cieco."

"Regola quattro: dry-run prima di ogni deploy. Quando modifico il prompt o aggiungo un nuovo competitor, lancio sempre PRIMA con claude trattino trattino dry-run. Claude esegue tutta la logica ma NON scrive nel database, NON manda email, NON modifica file. Solo logga quello che AVREBBE fatto. Leggo l'output. Se mi convince, lo metto in produzione. Se non mi convince, rivedo il prompt."

"Regola cinque: budget API con alert. Nella console Anthropic imposto un soft limit a cinquanta dollari mensili — sopra il quale mi arriva email — e un hard limit a duecento dollari — sopra il quale l'API key smette di funzionare. Cosi' anche col peggior bug possibile, anche con un loop infinito notturno, il danno massimo e' duecento dollari. Trenta secondi di setup, dormi tranquillo per sei mesi."
