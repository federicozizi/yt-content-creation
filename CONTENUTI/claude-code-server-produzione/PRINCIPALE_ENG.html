STEP 5

The 5 rules I now apply ALWAYS

What to show on screen

Full-screen, the 5 rules as numbered cards. As you discuss each, highlight the corresponding card. Below each card, a mini-icon of the file that implements it (e.g. settings.json icon, anthropic console icon).

  • Rule 1 — Never run as root
  • Rule 2 — Blocking hooks for destructive commands
  • Rule 3 — Aggressive logging always
  • Rule 4 — Dry-run before every deploy
  • Rule 5 — API budget with alerts and hard limit
What to say (verbatim)

"Rule one: never run Claude Code as the root user on the VPS. Create a dedicated user with minimum permissions. If Claude one day causes a mess — not out of malice but because the prompt was poorly written — damage is contained. If instead it runs as root, one wrong command is a catastrophe. It happened to me once: Claude tried to run an rm dash rf on a folder because it misinterpreted a prompt instruction. The claude user had no permissions, OS refused, saved. If it had been root, it was over."

"Rule two: blocking hooks for destructive commands. In the VPS settings.json file, I add a PreToolUse hook that intercepts every call to the Bash tool and blocks dangerous commands a priori — rm dash rf, sudo, dd, mkfs. Even if Claude tried them, the hook blocks them. Redundancy above OS permissions. The full file, production settings.json, is in the materials."

"Rule three: aggressive logging, always. Every execution, Claude writes a detailed log to slash var slash log slash claude dash scraper dot log. Start timestamp, decisions made, commands executed, end timestamp. When something goes wrong in the morning, I have the history of what happened. When everything's fine, I have metrics for tuning the prompt. Without logs, you're blind."

"Rule four: dry-run before every deploy. When I modify the prompt or add a new competitor, I always launch FIRST with claude dash dash dry-run. Claude runs all the logic but does NOT write to the database, does NOT send email, does NOT change files. Just logs what it WOULD HAVE done. I read the output. If I'm convinced, I push to production. If not, I revise the prompt."

"Rule five: API budget with alerts. In the Anthropic console I set a soft limit of fifty dollars monthly — above which I get email — and a hard limit of two hundred dollars — above which the API key stops working. So even in the worst possible bug scenario, even with an overnight infinite loop, the maximum damage is two hundred dollars. Thirty seconds of setup, sleep easy for six months."
