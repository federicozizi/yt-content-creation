System explainer: the internal assistant on Telegram

In one sentence

What we build

An agent on Telegram for the company's internal communications. Employees message it: it answers their questions by pulling from a "company handbook", and when someone requests time off, reports an absence or a fault, it actually logs the request in a register.

The difference that drives the whole video: a chatbot just talks. This one, at a certain point, stops talking and does something. It does something because it has tools — we call them "the agent's hands". That is what makes it a REAL agent.

How it's built

System architecture

A message comes in from Telegram on the left and sets the agent loop in motion: Claude reads with its "brain" (instructions + handbook), decides, and here the fork opens. If a reply is enough, it replies. If action is needed, it uses the hand — the registra_richiesta tool that writes into the register — sees the result, and goes back into the loop until it has the answer ready.

Piece by piece

How it works, piece by piece

1

The SDK and the tool runner — the "agent loop" the engine

The SDK is the official toolbox (the anthropic package) that lets your program talk to Claude. The key piece is the tool runner (client.beta.messages.tool_runner): it's the real agent loop. Claude reads → if needed it uses the tool → sees the result → continues, on its own, until it has the final answer. Without the tool runner we'd have to hand-write the "if the user says X then call Y" loop; with it, the SDK handles the loop.

2

The tool — the agent's "hands" the real action

A perfectly ordinary Python function, registra_richiesta(tipo, dipendente, dettaglio), that writes a line into the richieste.log register. What turns it into a tool Claude can use is the @beta_tool decorator. Its description (the docstring) is not a comment for us: it's the note Claude reads to understand when to use the hand. The clearer it is, the better it decides. Here it says, in effect: "use this when an employee requests time off or reports a fault".

3

The brain — instructions + company handbook who it is and what it knows

Two things. The system instructions (the SYSTEM block) tell Claude who it is and how to behave: answer in Italian, be brief, use only the handbook's info, and if you don't know something, admit it instead of making it up. The company handbook (azienda_knowledge.md) is its memory: hours, time off, contacts, rules. It's written in plain language, anyone can update it, no code. The tidier it is, the better the agent answers.

4

The Telegram bridge — listening, no open ports the agent's face

Telegram gives the agent a "face". The on_message function receives every message, the tool runner kicks off, and reply_text sends the answer back. The bot needs no server with open ports: it listens — every moment it asks Telegram "any messages for me?" (in jargon, polling). So it runs perfectly fine from your own computer, no need to call IT.

The point of the video

Why it's a REAL agent (not a chatbot)

The whole series lives in this sentence: a chatbot talks; an agent talks AND does. The difference isn't how "smart" the model is — it's that we gave the agent hands (the tools), and at a certain point, on its own, it stops talking and acts.

CHATBOT

Just talks
  • You ask it something, it answers.
  • It can only produce text.
  • "I'd like time off from the 12th to the 16th" → it replies "sure, you need 7 days' notice"… and that's where it ends.
  • Nothing changes in the real world. A clever parrot.

AGENT

Talks AND does
  • You ask it something, and if needed it acts.
  • Beyond talking, it has hands (the tools).
  • "I'd like time off from the 12th to the 16th" → it decides on its own to use the hand and logs the request.
  • Something actually changes: a new line appears in the register.
☞ The difference shows on screen: richieste.log with one extra line.

The "wow" moment of the video is exactly this: you type the time-off request and, instead of a plain "ok", a new line appears in the register. Right there the viewer sees, with their own eyes, the agent that does and not just says.

Honesty

What the system does NOT do

It logs, but doesn't approve. The agent records the time-off request; the final word stays with a human. And rightly so: the tool prepares the work, it doesn't decide in the manager's place.

It only knows what's in the handbook. It answers with the information in azienda_knowledge.md and, if it doesn't have it, it says so instead of making it up — which is exactly what you want from a work tool.

It's the basic version. It runs while the program is on and has no memory of conversations between restarts. Keeping it always on, giving it memory, and connecting it to email and the management system are the building blocks of the next episodes.

The folder you hand over

What's in the materials

It's the materiali/ folder the viewer downloads and that you zip up at the end of the video. A handful of files, each with a precise role. Here's how it's laid out and how the pieces talk to each other.

FileWhat it is / what it's for
agente_telegram.pyThe program itself: the agent loop (the SDK's tool runner), the registra_richiesta tool — "the agent's hands" — and the bridge to Telegram. It's the heart of the system.
azienda_knowledge.mdThe "brain": the company handbook (hours, leave, contacts, rules) the agent draws on to answer. The viewer swaps in their own company's data.
.env.exampleThe template for the credentials file. You copy it to .env and paste in the two keys: ANTHROPIC_API_KEY (unlocks Claude) and TELEGRAM_BOT_TOKEN (controls the bot).
requirements.txtThe list of packages to install (anthropic, python-telegram-bot, python-dotenv) with pip install -r.
.gitignoreThe safety net for Git: it excludes .env, richieste.log and __pycache__, so credentials and employee data never end up online.
README.mdThe step-by-step guide for the public: how to switch the agent on from scratch (the two keys, how to create the .env, how to test it).
DISCLAIMER.mdThe note on the safety of the two keys (don't share them, revoke them if they end up online) and on the employee data in the log.
richieste.logNot there at the start: the agent creates it when it files the first request. It's the request log (leave/absence/IT), one line per request.

In one line: the message coming in from Telegram goes into agente_telegram.py, which uses azienda_knowledge.md as its knowledge to answer and the tool to write into richieste.log (output); .env holds the two keys. README and DISCLAIMER are the instructions; .env.example, .gitignore and requirements.txt are there to get everything running safely.

Try it — operational part

How to test the system (with the course materials)

Everything you need is in the materiali/ folder. This is the exact sequence to switch the agent on and verify, with your own eyes, that it really does the thing that makes it a REAL agent: not just reply, but act.

  1. Open the materiali folder in VS Code and open the integrated terminal (Terminal → New Terminal).
  2. Install the dependencies: pip install -r requirements.txt
  3. Set up two keys in the .env file (copy .env.example to .env): your ANTHROPIC_API_KEY and the TELEGRAM_BOT_TOKEN — the latter is given to you by @BotFather on Telegram by sending /newbot.
  4. Start the agent: python agente_telegram.py

What you should see (the script prints it in the terminal):

Agente in ascolto su Telegram. Premi CTRL+C per fermarlo.

(That's Italian for "Agent listening on Telegram. Press CTRL+C to stop it.") From here on the agent is alive: open Telegram, find your bot and message it. Every message you send runs through the agent loop.

Proof that each piece works:
  • Send the bot a question covered by the handbook (e.g. "What time does the office close on Friday?") → it answers by pulling from azienda_knowledge.md = the "brain" works.
  • Send "I'd like time off from August 12th to 16th" → the bot confirms and a new line appears in the richieste.log file → the tool has acted: this is what makes it a real agent, not a chatbot.
  • Send something that is NOT in the handbook → it admits it doesn't know instead of making it up.

Two extra checks (optional):

• Look at the mark the hand left. Open richieste.log: the time-off request is there, recorded as a line in JSON format (type, employee, detail). It's the concrete trace that the agent didn't just talk — it acted.

• With your own data. Open azienda_knowledge.md in VS Code, replace the sample data (Acme S.r.l.) with your own company's — hours, time off, contacts — save and re-run. The agent's answers change accordingly: same system, your company inside.

How much does the test cost? A few messages to the agent cost a fraction of a cent: the model in use (claude-opus-4-8) is paid only for the text it reads and writes, and here that's very little. To spend even less, switch the model in the code to claude-haiku-4-5 (a single line).
