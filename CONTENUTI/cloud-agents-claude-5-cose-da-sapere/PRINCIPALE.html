STEP 1 (COSA #1)

Non sono Claude Code locale — sono "stagisti che lavorano la notte"

Cosa mostrare a schermo

Lavagna (digitale). Disegna in diretta due rettangoli affiancati:

  • Sinistra: "CLAUDE CODE LOCALE" - icona del tuo terminale, una linea retta che lo collega ai tuoi file VS Code
  • Destra: "CLOUD AGENT" - icona di una nuvola, con un omino dentro che lavora, e sotto la dicitura "il tuo PC e' spento"
  • Una freccia dal Cloud Agent verso una "scatola GitHub" da cui parte poi una linea verso il tuo PC al mattino
Cosa dire (verbatim)

"Cosa numero uno, e probabilmente la piu' importante per capire tutto il resto: i Cloud Agent NON sono Claude Code locale. Sono due cose diverse, vivono in due posti diversi, fanno due lavori diversi."

"Claude Code, quello che apri sul terminale, gira sul tuo PC e lavora coi TUOI file aperti in VS Code. E' interattivo — tu scrivi, lui risponde, voi due insieme costruite qualcosa."

"Il Cloud Agent gira su una macchina di Anthropic, nel cloud. Quando tu non sei davanti al PC. Anzi: quando tu sei in vacanza, quando tu dormi, quando tu sei in palestra. Lui esegue un task ricorrente che gli hai detto di fare — tipo 'ogni mattina alle otto cerca le news AI piu' importanti e scrivimi un riassunto'."

"L'analogia che mi aiuta a ricordarlo: i Cloud Agent sono come stagisti che lavorano la notte mentre dormi. Gli lasci un foglio di istruzioni sulla scrivania, loro arrivano alle quattro del mattino, lavorano, e quando tu arrivi alle otto trovi il risultato pronto sulla scrivania. Tu non li hai mai visti lavorare, ma il lavoro e' fatto."

STEP 2 (COSA #2)

Servono per task RICORRENTI, non per quelli singoli

Cosa mostrare a schermo

Doppia colonna a schermo, titolo "USAlI QUI" a sinistra, "NON QUI" a destra. Riempi a mano (digitalmente) con 3 esempi per ciascuna colonna:

  • USALI: scouting news mattutino, monitor competitor settimanale, customer support digest, report mensile vendite
  • NON QUI: aiutami a scrivere questa mail ORA, modifica questo Excel adesso, debugga il mio script Python che e' rotto
Cosa dire (verbatim)

"Cosa numero due: i Cloud Agent danno valore solo se il task si ripete. Ricorrente. Frequenza prevedibile. Non sono un sostituto della chat normale per le cose una tantum."

"Casi reali dove funzionano. Scouting di news quotidiano — ogni mattina alle otto vede cosa e' successo nel tuo settore, ti scrive un report. Monitor competitor settimanale — ogni lunedi' controlla i prezzi e i nuovi prodotti dei tuoi tre concorrenti principali, ti dice cosa e' cambiato. Customer support digest — ogni venerdi' sintetizza i ticket della settimana, identifica i temi ricorrenti, ti propone migliorie. Pattern comune: la cosa serve ogni X giorni, non ogni mezz'ora."

"Dove non hanno senso. Aiutami a scrivere questa email adesso? Usa la chat normale, e' istantanea. Modifica questo file di Excel? Il file e' sul tuo PC, il Cloud Agent non lo vede. Debugga il mio script? Quello fallo con Claude Code in locale dove hai i file aperti. Cloud Agent e' uno strumento specifico per una cosa specifica — non sostituisce ne' la chat ne' Claude Code locale."

STEP 3 (COSA #3)

Consumano quota del tuo piano — fai i conti

Cosa mostrare a schermo

Slide a tutto schermo con tabella semplice:

  • 1 routine al giorno -> circa 5 GB context/mese
  • 1 routine ogni 12 ore (2 al giorno) -> circa 10 GB
  • 5 routine ognuna 1 volta al giorno -> circa 25 GB

Sotto, una piccola riga "Piano Pro: ~7 GB/mese | Piano Max: ~50 GB/mese". Indica con una freccia visiva che 2+ routine giornaliere richiedono Max.

Cosa dire (verbatim)

"Cosa numero tre, e qui faccio cifre concrete perche' nessuno te le dice in chiaro. I Cloud Agent NON sono gratis. Consumano quota del tuo piano Pro o Max."

"Quanto consumano? Una routine di scouting news standard — che fa cinque-sei chiamate WebSearch, dieci chiamate WebFetch, e poi scrive un file di riassunto — equivale piu' o meno a quaranta-sessanta messaggi di chat normale. Se la fai girare una volta al giorno per un mese, consumi circa cinque GB di context. Se la fai girare due volte al giorno, dieci GB."

"Il piano Pro ti da' circa sette GB al mese. Tradotto: con Pro ci sta UNA routine al giorno. Due routine giornaliere significa upgrade a Max — che ha una quota molto piu' alta, parliamo di cinquanta GB. Non spaventarti — ma fai i conti prima di buttarne in piedi cinque."

"La regola che do sempre: parti con UNA routine. Per le prime due settimane misura nella pagina di billing su claude punto ai quanto consuma davvero. Solo dopo aggiungi la seconda. Niente foga di automatizzare tutto subito."

STEP 4 (COSA #4)

GitHub e' la scrivania su cui il Cloud Agent lascia il foglio

Cosa mostrare a schermo

Lavagna o slide. Disegna:

  • Sandbox cloud (nuvola) - il Cloud Agent dentro
  • Una freccia "git clone" che parte da un repository GitHub verso la nuvola
  • Una freccia "git push" che torna indietro
  • Sotto la nuvola scritta: "sandbox effimero — si autodistrugge dopo l'esecuzione"
  • Sotto GitHub: "persistente, vede chi vuoi tu"
Cosa dire (verbatim)

"Cosa numero quattro — qui c'e' un dettaglio che, se non capisci, non riesci a far funzionare niente. Il sandbox dove gira il Cloud Agent e' EFFIMERO. Tradotto: si autodistrugge dopo ogni esecuzione. Nessuna memoria tra una run e l'altra."

"Vuol dire una cosa precisa: se l'agente scrive un file, e quel file resta SOLO dentro il sandbox, alla fine dell'esecuzione lo perdi. Devi mettere il file da qualche parte di permanente. E quel posto, a oggi, e' GitHub."

"L'analogia che uso: il Cloud Agent va a lavorare in un ufficio condiviso. Quando finisce, deve mettere i fogli in una cartella ben precisa — il tuo repository GitHub — altrimenti se ne va a casa e i fogli vengono buttati via."

"Praticamente: ogni Cloud Agent e' associato a un repository GitHub. All'inizio dell'esecuzione lui fa git clone del repo. Lavora. Alla fine fa git commit e git push dei nuovi file. Tu, dal tuo PC, fai git pull e vedi il risultato. E' il modo in cui il lavoro fatto nel cloud arriva sulla tua scrivania."

"Una nota tecnica importante: il push richiede credenziali — il sandbox non ha automaticamente accesso al tuo GitHub. Devi dargli una chiave, che si chiama Personal Access Token. Lo crei in trenta secondi da GitHub, ne parlo nei materiali. Senza quella chiave, il Cloud Agent puo' fare tutto il lavoro che vuole, ma alla fine non te lo consegna."

STEP 5 (COSA #5)

L'approvazione umana resta — sempre, su tutto cio' che esce

Cosa mostrare a schermo

Doppia colonna a schermo:

  • Verde a sinistra "OK delegare": genera bozze email, scrivi report PDF, identifica problemi e proponi azioni
  • Rosso a destra "MAI delegare": invia email vere ai clienti, esegui pagamenti, cancella record, ordina merci automaticamente
Cosa dire (verbatim)

"Cosa numero cinque, e questa e' una regola di sano metodo non di tecnica. Anche se il Cloud Agent gira da solo, l'approvazione umana sulle azioni che toccano l'esterno resta SEMPRE obbligatoria."

"Cosa significa in pratica? Esempi. Va benissimo dire al Cloud Agent 'genera cinque bozze di email di sollecito e salvale nei draft di Gmail' — perche' tu domani le rivedi e clicchi Invia tu. Va benissimo dire 'identifica i prodotti a rischio esaurimento e scrivimeli in un file' — perche' tu poi decidi cosa riordinare. Va benissimo 'genera il report mensile delle vendite' — perche' e' un documento che leggi e usi."

"NON va bene 'manda cinque email vere ai clienti', 'fai un pagamento al fornitore', 'cancella i record dei clienti inattivi', 'ordina le scorte mancanti'. Anche se il modello fosse tecnicamente in grado di farlo, e in molti casi lo e', tu NON gli dai mai questa autonomia. Il giudizio finale su cose che toccano clienti, soldi, dati persi, resta sempre tuo."

"Regola d'oro: il Cloud Agent prepara, tu confermi. Sempre. Specie all'inizio. Dopo sei mesi che lavori con lui e ti fidi al cento percento del suo comportamento, puoi automatizzare qualche azione esterna a basso rischio — ma e' una scelta che fai consapevolmente, non per default."

STEP 6

Build pratico — la routine che genera idee per questo canale

Cosa mostrare a schermo

Schermo diviso in tre momenti:

  • 1. Browser su github.com/new: crei un repo chiamato "claude-routines-personali"
  • 2. Browser su github.com/settings/tokens/new: crei un PAT con scope `repo`. **COPRI il token con un rettangolo nero in post**.
  • 3. Browser su claude.ai/code/routines: New Routine, compili nome ("scouting-news-mattina"), cron ("0 6 * * *"), repository, prompt (mostri brevemente il template di esempio-routine.md), allowed tools (Bash, Read, Write, WebSearch, WebFetch).
  • 4. Click "Run now" -> dopo 3-5 minuti, sul repo GitHub appare un nuovo commit con il file delle news del giorno
  • 5. Apri il file su GitHub, mostra il contenuto: report mattutino con 5 spunti operativi
Cosa dire (verbatim)

"Adesso ti faccio vedere come ho costruito la routine che gira ogni giorno alle otto del mattino per questo canale. Tre setup veloci, poi la routine vera."

"Primo: vado su github punto com slash new e creo un repository chiamato 'claude-routines-personali'. Privato, perche' i risultati delle routine possono essere informazioni sensibili. Click Create."

"Secondo: vado su github punto com slash settings slash tokens slash new. Creo un Personal Access Token — la chiave che dirò al sandbox di usare per pushare i risultati. Nome 'claude-routines-pat', scope 'repo', click Generate. Mi compare il token che inizia con ghp underscore — lo copio subito, lo salvo nel mio gestore di password. Ovviamente a video lo censuro per ovvi motivi di sicurezza."

"Terzo: claude punto ai slash code slash routines. New Routine. Nome: scouting-news-mattina. Schedule: ogni giorno alle sei UTC, che in Italia significa otto del mattino in estate. Repository: l'URL di quello che ho appena creato. Prompt: lo copio da un template che ho preparato per voi nei materiali, mi basta sostituire quattro placeholder — il tema del mio scouting, le fonti che voglio scansionare, le mie credenziali GitHub. Allowed tools: bash, read, write, websearch, webfetch. Save."

"Per testare, click Run Now. Non aspetto il prossimo cron. In tre-cinque minuti vedo che il sandbox e' partito, ha fatto le sue ricerche, ha scritto un file, ha pushato sul repo GitHub. Vado su GitHub, ed ecco il file: news della giornata, formato markdown, cinque spunti operativi con link verificati. Pronto sulla scrivania. Da domani mattina alle otto, lo trovero' li' senza che io faccia niente."
