STEP 1 (THING #1)

They're not local Claude Code — they're "interns working the night shift"

What to show on screen

Whiteboard (digital). Draw live two side-by-side boxes:

  • Left: "LOCAL CLAUDE CODE" - your terminal icon, a straight line connecting it to your VS Code files
  • Right: "CLOUD AGENT" - a cloud icon, with a worker inside, and below the caption "your PC is off"
  • An arrow from Cloud Agent to a "GitHub box", and from there a line back to your PC in the morning
What to say (verbatim)

"Thing number one, probably the most important one to understand everything else: Cloud Agents are NOT local Claude Code. They're two different things, living in two different places, doing two different jobs."

"Claude Code, the one you open in your terminal, runs on YOUR PC and works with YOUR files open in VS Code. It's interactive — you type, it answers, the two of you build something together."

"The Cloud Agent runs on a machine at Anthropic, in the cloud. When you're NOT at your computer. Actually: when you're on vacation, when you sleep, when you're at the gym. It executes a recurring task you've assigned to it — something like 'every morning at eight, find the most important AI news and write me a summary'."

"The analogy that helps me remember: Cloud Agents are like interns working the night shift while you sleep. You leave a sheet of instructions on the desk, they show up at four in the morning, they work, and when you arrive at eight you find the result ready on the desk. You never saw them work, but the work is done."

STEP 2 (THING #2)

They're for RECURRING tasks, not one-off ones

What to show on screen

Two-column layout on screen, "USE HERE" on the left, "NOT HERE" on the right. Fill in (live, digitally) with 3 examples per column:

  • USE HERE: morning news scouting, weekly competitor monitoring, customer support digest, monthly sales report
  • NOT HERE: help me write this email NOW, edit this Excel file right now, debug my Python script that's broken
What to say (verbatim)

"Thing number two: Cloud Agents are valuable only if the task repeats. Recurring. Predictable frequency. They're not a substitute for the regular chat for one-off things."

"Real cases where they work. Daily news scouting — every morning at eight it looks at what happened in your industry, writes you a report. Weekly competitor monitoring — every Monday checks prices and new products of your three main competitors, tells you what changed. Customer support digest — every Friday it summarizes the week's tickets, identifies recurring themes, suggests improvements. Common pattern: the thing is needed every X days, not every half hour."

"Where they don't make sense. Help me write this email now? Use the regular chat, it's instant. Edit this Excel file? The file is on your PC, the Cloud Agent can't see it. Debug my script? Do that with Claude Code locally, where you have the files open. Cloud Agent is a specific tool for a specific job — it doesn't replace the chat or local Claude Code."

STEP 3 (THING #3)

They consume your plan's quota — do the math

What to show on screen

Full-screen slide with simple table:

  • 1 routine per day -> about 5 GB context/month
  • 1 routine every 12 hours (2 per day) -> about 10 GB
  • 5 routines, each running once a day -> about 25 GB

Below, a small line "Pro plan: ~7 GB/month | Max plan: ~50 GB/month". Indicate with a visual arrow that 2+ daily routines require Max.

What to say (verbatim)

"Thing number three, and here I'll give you actual numbers because nobody tells you this clearly. Cloud Agents are NOT free. They consume quota from your Pro or Max plan."

"How much? A standard news-scouting routine — five-six WebSearch calls, ten WebFetch calls, then writing a summary file — roughly equals forty-to-sixty regular chat messages. If you run it once a day for a month, that's about five GB of context. If you run it twice a day, ten GB."

"The Pro plan gives you about seven GB a month. Translated: with Pro, one routine a day fits. Two daily routines means upgrade to Max — which has a much higher quota, around fifty GB. Don't panic — but do the math before launching five of them."

"The rule I always give: start with ONE routine. For the first two weeks measure on the claude dot ai billing page how much it actually consumes. Only then add the second one. No rush to automate everything immediately."

STEP 4 (THING #4)

GitHub is the desk where the Cloud Agent leaves the sheet

What to show on screen

Whiteboard or slide. Draw:

  • Cloud sandbox (cloud icon) - the Cloud Agent inside
  • A "git clone" arrow going from a GitHub repository to the cloud
  • A "git push" arrow going back
  • Under the cloud: "ephemeral sandbox — self-destructs after execution"
  • Under GitHub: "persistent, only the people you allow can see it"
What to say (verbatim)

"Thing number four — here there's a detail that, if you miss it, nothing works. The sandbox where the Cloud Agent runs is EPHEMERAL. Translated: it self-destructs after every execution. No memory between runs."

"That means a precise thing: if the agent writes a file, and that file stays ONLY inside the sandbox, you lose it at the end of execution. You need to put the file somewhere permanent. And that place, today, is GitHub."

"My favorite analogy: the Cloud Agent goes to work in a shared office. When done, it has to put the papers in a very specific folder — your GitHub repository — otherwise it goes home and the papers get thrown out."

"Practically: every Cloud Agent is associated with a GitHub repository. At the start of execution it does git clone of the repo. Works. At the end it runs git commit and git push of the new files. You, from your PC, run git pull and see the result. That's how cloud work lands on your desk."

"One important technical note: the push requires credentials — the sandbox doesn't automatically have access to your GitHub. You give it a key, called a Personal Access Token. You create it in thirty seconds in GitHub, I cover this in the materials. Without that key, the Cloud Agent can do all the work it wants, but at the end it doesn't deliver it to you."

STEP 5 (THING #5)

Human approval stays — always, on everything that goes out

What to show on screen

Two-column layout:

  • Green left "OK to delegate": generate email drafts, write PDF reports, identify problems and suggest actions
  • Red right "NEVER delegate": send real emails to clients, execute payments, delete records, automatically order supplies
What to say (verbatim)

"Thing number five, and this is a sound-method rule rather than a technical one. Even if the Cloud Agent runs on its own, human approval on outgoing actions ALWAYS stays mandatory."

"What does that mean in practice? Examples. It's fine to tell the Cloud Agent 'generate five reminder email drafts and save them in Gmail drafts' — because you review and click Send tomorrow. It's fine 'identify products at risk of running out and write them in a file' — because you decide what to reorder. It's fine 'generate the monthly sales report' — because that's a document you read and use."

"It's NOT fine 'send five actual emails to these clients', 'make a payment to this vendor', 'delete records of inactive clients', 'order missing stock automatically'. Even if the model is technically able to do it — and in many cases it is — you NEVER give it that autonomy. Final judgment on things touching clients, money, or lost data, always stays with you."

"Golden rule: Cloud Agent prepares, you confirm. Always. Especially at the start. After six months of working with it and full trust in its behavior, you can automate some low-risk external actions — but that's a choice you make consciously, not by default."

STEP 6

Practical build — the routine that generates ideas for this channel

What to show on screen

  • 1. Browser on github.com/new: create a repo called "claude-routines-personali"
  • 2. Browser on github.com/settings/tokens/new: create a PAT with `repo` scope. **COVER the token with a black box in post**.
  • 3. Browser on claude.ai/code/routines: New Routine, fill in name ("scouting-news-mattina"), cron ("0 6 * * *"), repository, prompt (briefly show the esempio-routine.md template), allowed tools (Bash, Read, Write, WebSearch, WebFetch).
  • 4. Click "Run now" -> after 3-5 minutes, a new commit appears on the GitHub repo with the day's news file
  • 5. Open the file on GitHub, show the content: morning report with 5 actionable insights
What to say (verbatim)

"Now let me show you how I built the routine that runs every morning at eight for this channel. Three quick setups, then the real routine."

"First: I go to github dot com slash new and create a repository called 'claude-routines-personali'. Private, because the routine results can contain sensitive info. Click Create."

"Second: I go to github dot com slash settings slash tokens slash new. I create a Personal Access Token — the key I'll tell the sandbox to use for pushing results. Name 'claude-routines-pat', scope 'repo', click Generate. I see the token starting with ghp underscore — I copy it immediately, save it in my password manager. Obviously I censor it on camera for obvious security reasons."

"Third: claude dot ai slash code slash routines. New Routine. Name: scouting-news-mattina. Schedule: every day at six UTC, which in Europe means eight in the morning in summer. Repository: the URL I just created. Prompt: I copy from a template I prepared for you in the materials, I just substitute four placeholders — the topic of my scouting, the sources I want to scan, my GitHub credentials. Allowed tools: bash, read, write, websearch, webfetch. Save."

"To test, click Run Now. I don't wait for the next cron. In three-five minutes I see the sandbox started, ran its searches, wrote a file, pushed to the GitHub repo. I go to GitHub, and here's the file: news of the day, markdown format, five actionable insights with verified links. Ready on the desk. From tomorrow morning at eight, I'll find it there without doing anything."
