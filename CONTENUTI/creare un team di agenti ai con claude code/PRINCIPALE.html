Cos'è un team di agenti AI

È un gruppo di chiamate Claude — ognuna con un ruolo specifico — che lavorano in parallelo sulla stessa attività. Ognuno fa una cosa sola, e poi un quarto agente raccoglie i risultati e li sintetizza.

Un agente solo che fa tutto si confonde. Quattro agenti specializzati no.

Quando l'attività è ricorrente — controlli da fare ogni mattina, dati da raccogliere ogni settimana, report da generare ogni mese — un team di agenti diventa un dipendente che non dorme. Lo costruisci una volta, lavora per te ogni giorno.

Quando ha senso

Quando devi:

  • Toccare più fonti diverse (siti, file, API, social)
  • Applicare filtri distinti per ogni fonte
  • Aggregare i risultati in un output unificato

Casi tipici: monitoraggio competitor, lead research, content radar, account-based monitoring, due diligence. Tutti lo stesso pattern.

Cosa costruiremo oggi

Per dimostrare il pattern useremo un esempio concreto: un team che ti manda un brief sui competitor ogni mattina alle 7.

Lo costruiremo in 3 modi diversi, tutti dentro l'ecosistema Anthropic. Stesso obiettivo, livelli di astrazione diversi: dal più "premasticato" (Claude Code che orchestra da solo) al più "low-level" (tu scrivi il loop con l'SDK base). Vedrai pro e contro di ognuno, e scegli tu quale fa per te.

In tutti e 3 i metodi il sistema fa la stessa cosa: alle 7 del mattino apre i siti dei tuoi 3 competitor, controlla 3 cose (prezzi, novità prodotto, post LinkedIn forti), sintetizza tutto, e ti consegna il brief. Tu apri la mail, in 30 secondi sai cos'è successo.

Esempio del brief

# Daily Competitor Brief — 5 maggio 2026 ## TOP INSIGHT 1. Acme ha alzato il prezzo del piano Pro del +15% 2. Beta Inc ha lanciato l'integrazione con Notion ieri 3. Gamma Co ha pubblicato un case study su LinkedIn (310 reactions) ## Per competitor ### Acme - Pricing: piano Pro €49 → €56 (+15%) - Features: nessun annuncio rilevante - Social: 2 post settimanali, engagement medio ### Beta Inc - Pricing: invariato - Features: lancio integrazione Notion (4 maggio) - Social: top post del lancio (180 reactions) ### Gamma Co ...
Importante: il brief competitor è solo l'esempio. Il pattern (4 ruoli specializzati + orchestrazione + scheduling) vale per qualunque attività ricorrente. A fine video vediamo come applicarlo a lead research, content radar, e altri casi.

I 3 metodi che vedrai

Costruiremo lo stesso sistema in 3 modi diversi, tutti dentro l'ecosistema Anthropic. La differenza è quanta della complessità si occupa Claude e quanta resta a te.

Spiegato al volo, in 3 frasi:
  • A Apri Claude Code nel terminale e gli dici "fai il brief". Lui legge i 4 ruoli (file .md) e li orchestra da solo. Tu non scrivi una riga di codice.
  • B Scrivi tu in Python 4 funzioni che chiamano l'API di Claude, una per ogni ruolo. Gestisci tu parallelismo, tool e gestione errori. Massimo controllo, massimo lavoro.
  • C Scrivi un Python molto corto che usa l'Agent SDK per caricare gli stessi 4 file .md del Metodo A e li orchestra al posto tuo. È "Claude Code embedded nel tuo script".

Analogia: stesso cervello (i 4 .md), tre modi diversi di svegliarlo. In tutti e 3 i casi il modello AI gira sui server di Anthropic — quello che cambia è solo dove sta il codice che decide quando chiamarlo.

A Claude Code Agent Teams + Routines

Il livello più alto di astrazione. Zero codice, solo file di istruzioni in markdown. Claude Code orchestra tutto da solo, le Routines lo schedulano sui server di Anthropic. Per chi è a suo agio col terminale e ha già il piano Claude Pro.

B Anthropic SDK (raw) + asyncio + cron

Il livello più basso. Tu costruisci tutto: il loop di chiamate, il parallelismo con asyncio.gather(), l'invio mail. ~150 righe di codice, gira ovunque ci sia Python. Massimo controllo, costo minimo. Per chi sa cos'è pip install e vuole un sistema che può integrare nel suo stack aziendale.

C Claude Agent SDK + subagent nativi

La via di mezzo. È Claude Code come libreria Python: l'SDK ufficiale Anthropic che porta dentro il tuo script lo stesso agent loop, gli stessi tool built-in (WebFetch, Read, Write) e — soprattutto — la stessa feature subagent del Metodo A. Riusi gli identici file .claude/agents/*.md del Metodo A, ma li lanci da uno script. ~50 righe di Python, niente loop tool-use scritto a mano.

⚙️ Setup iniziale: i prerequisiti comuni

Tre cose servono indipendentemente dal metodo che scegli. Falle ora una volta sola, le riusi per qualunque metodo (o anche per tutti e tre, se vuoi provarli).

1. Claude Code A B C

Claude Code è l'assistente AI che ti guida nel setup di ogni metodo. È lui che legge il file INIZIO_QUI.md e fa tutto automaticamente: installa dipendenze, configura il progetto, ti chiede solo le informazioni che servono.

Puoi usarlo in due modi:

  • App Desktop (consigliato) — scarica l'app da claude.ai/download, installala, accedi col tuo account Anthropic. Hai un'interfaccia grafica con terminale integrato, editor di file, e le sessioni parallele degli agenti tutte visibili nella sidebar.
  • Terminale CLI — se preferisci lavorare dal terminale classico (vedi l'approfondimento tecnico in fondo a ogni metodo per i comandi di installazione).

Per il Metodo A serve il piano Pro ($20/mese). Per i Metodi B e C basta l'account gratuito con credito API.

2. API key Anthropic A B C

Serve a tutti e 3 i metodi. Si crea in 1 minuto e costa $0 finché non la usi (paghi solo le chiamate effettive, ~$1-2/mese per il nostro brief quotidiano).

  1. Vai su console.anthropic.com e accedi (o registrati se è la prima volta)
  2. Menu a sinistra → Settings → API Keys
  3. Clicca Create Key. Nome suggerito: team-agenti-competitor
  4. Copia subito la chiave (formato sk-ant-...) e salvala in un posto sicuro: dopo che chiudi la finestra non la rivedi più
  5. Vai su Settings → Billing e aggiungi un metodo di pagamento. Imposta un spending limit di $5/mese per stare tranquillo
Quanto costa davvero? Il brief usa ~30k token al giorno = circa $0,05/giorno = $1,50/mese. Lo spending limit a $5 è un margine abbondante per non preoccuparti.

3. App Password Gmail B C

Serve solo per i metodi B e C, che mandano il brief per email via SMTP. Il Metodo A invece scrive un file markdown nel repo Git, niente email.

Una App Password è un codice usa-e-getta a 16 caratteri che permette agli script di mandare mail per tuo conto, senza esporre la password vera. Google la richiede per qualunque uso "automatico" di Gmail.

  1. Vai su myaccount.google.com/security
  2. Verifica che la verifica in 2 passaggi sia attiva (è prerequisito obbligatorio per generare app password). Se è disattiva, attivala ora — bastano 2 minuti
  3. Vai su myaccount.google.com/apppasswords
  4. Nome dell'app: scrivi team-agenti e clicca Crea
  5. Google mostra un codice tipo abcd efgh ijkl mnop. Copialo subito (anche qui: una volta chiusa la finestra non lo rivedi)
Non confondere: la password normale di Gmail NON funziona per SMTP da script. Ti serve l'App Password generata sopra. Se provi con quella normale ricevi 535 Authentication failed.
Non usi Gmail? Outlook, Yahoo, ProtonMail e i provider self-hosted hanno tutti SMTP. Cambia smtp.gmail.com nello script con il server del tuo provider e usa le credenziali normali (Outlook richiede invece OAuth: in quel caso meglio usare un servizio come Resend o SendGrid, gratuiti fino a 3000 mail/mese).

4. Sicurezza credenziali: il .gitignore A B C

Tutti e 3 i metodi salvano credenziali sensibili in locale (chiave Anthropic, App Password Gmail). Se le committi su Git per sbaglio anche solo una volta, sono compromesse per sempre: anche dopo averle rimosse, restano nella storia git e bot automatici scansionano GitHub di continuo cercando proprio queste stringhe.

Per evitarlo: ogni cartella materiali contiene un file .gitignore pronto. Copialo nella radice del tuo progetto PRIMA di fare il primo git init. Esclude:

  • .env — il file con le credenziali (Metodi B e C)
  • .claude/settings.local.json — settings locali Claude Code (Metodi A e C)
  • .venv/, __pycache__/ — ambiente Python (Metodi B e C)
  • briefs/, logs/ — output che si rigenerano automaticamente
Se hai già committato per sbaglio: revoca subito la chiave su console.anthropic.com → Settings → API Keys → revoke. E revoca l'App Password Gmail su myaccount.google.com/apppasswords. Poi crea credenziali nuove. Rimuoverle dalla storia git da sole non basta.

A Metodo A: Claude Code Agent Teams + Routines

L'idea

Claude Code ha 3 feature native che messe insieme fanno un team di agenti senza scrivere codice:

  • Sub-agent definitions — ogni ruolo è un file .md in .claude/agents/. Frontmatter YAML per nome/strumenti/modello, body con le istruzioni.
  • Agent Teams — feature che permette a Claude Code di lanciare 4 sessioni parallele che si parlano tra loro tramite shared task list. Sperimentale, ma stabile in pratica.
  • Claude Routines — scheduler cloud Anthropic. Dichiari prompt + cron, gira sui server di Anthropic anche col laptop spento. Incluso nel piano Pro.

Perché sceglierlo

  • Zero codice. Zero terminale dopo il setup. Solo prompt in markdown.
  • Scheduling nativo Anthropic, niente VPS, niente computer da tenere acceso
  • Il piano Pro che usi già copre tutto — niente abbonamenti extra

Quando NON sceglierlo

  • Se vuoi integrare il sistema in un repo aziendale con CI/CD: meglio Python
  • Se vuoi integrare il sistema in CI/CD o in un repo aziendale: meglio il Metodo B (Anthropic SDK) o il Metodo C (Agent SDK)
  • Se vuoi evitare feature in research preview: meglio il Metodo B (Anthropic SDK)

Architettura

⏰ Claude Routine (daily 7:00) → 🧠 Team Lead → spawn parallel │ ┌───────────────────┬───────────────────┐ ▼ ▼ ▼ pricing-watcher feature-watcher social-watcher │ │ │ └───────────────────┼───────────────────┘ ▼ 🎯 synthesizer → briefs/YYYY-MM-DD.md

B Metodo B: Python + Anthropic SDK + cron

L'idea

Un singolo file Python di ~150 righe che fa tutto: 3 chiamate watcher in parallelo con asyncio.gather(), una chiamata synthesizer in coda, invio mail con smtplib. Niente magia: 4 funzioni, ognuna con il suo compito.

Il pezzo critico è asyncio.gather():

findings = await asyncio.gather( watcher("pricing", load_prompt("pricing.txt"), competitors), watcher("features", load_prompt("features.txt"), competitors), watcher("social", load_prompt("social.txt"), competitors), )

5 righe e i 3 watcher partono contemporaneamente. Il tempo totale è quello del watcher più lento, non la somma di tutti e 3.

Perché sceglierlo

  • Massima portabilità: lo script gira ovunque ci sia Python (laptop, VPS, Docker, GitHub Actions, AWS Lambda)
  • Costo minimo: ~$1-2/mese di sole API, niente abbonamenti
  • Massimo controllo: ogni byte è codice tuo, modifichi tutto come vuoi
  • SDK Anthropic stabile da anni, niente feature sperimentali
  • Si integra in repo aziendali, CI/CD, Docker, FastAPI, Kubernetes

Quando NON sceglierlo

  • Se non hai mai usato Python: meglio il Metodo A (Claude Code) — zero codice, solo prompt in markdown
  • Se vuoi tutto su un'unica piattaforma senza terminale: meglio il Metodo A (Claude Code)
  • Se non vuoi gestire scheduling esterno (cron / GitHub Actions): meglio il Metodo A con Routines cloud Anthropic

Architettura

⏰ cron (locale o GitHub Actions) → python team_agenti.py │ asyncio.gather( fan-out parallelo ┌───────────────────┬───────────────────┐ ▼ ▼ ▼ pricing watcher features watcher social watcher (Sonnet) │ │ │ └───────────────────┼───────────────────┘ ) fan-in ▼ synthesizer (Opus) → briefs/YYYY-MM-DD.md + smtplib send mail

Claude Code fa tutto da solo: verifica che Python sia installato (e ti dice come installarlo se manca), crea l'ambiente virtuale, installa le dipendenze, e ti chiede una alla volta le credenziali (API key Anthropic, App Password Gmail) e i nomi dei tuoi 3 competitor. Fine.

C Metodo C: Claude Agent SDK + subagent nativi

L'idea

Il Claude Agent SDK è la libreria Python (e TypeScript) ufficiale di Anthropic che porta dentro al tuo script lo stesso motore che fa girare Claude Code. Stesso agent loop, stessi tool built-in (WebFetch, Read, Write, Bash, ...), stessa feature subagent.

La cosa interessante per noi: i sub-agent sono definiti esattamente nello stesso formato del Metodo A — file markdown con frontmatter YAML. Quindi i 4 file .claude/agents/*.md che hai scritto per Claude Code li riusi tali e quali qui. Cambia solo come li lanci: nel Metodo A usi il CLI, qui li lanci da Python.

Il pezzo che sorprende: parallelismo e tool sono built-in nell'SDK. Non scrivi asyncio.gather() a mano come nel Metodo B, non implementi il loop tool-use. Dichiari l'orchestrator, gli passi i 4 sub-agent, e chiedi "lancia i 3 watcher in parallelo poi il synthesizer". L'SDK fa il resto.

Perché sceglierlo

  • Riusi gli STESSI .md sub-agent del Metodo A — il prototipo CLI diventa script di produzione senza riscrivere nulla
  • ~50 righe di Python invece di 150: l'SDK gestisce loop, tool, parallelismo
  • Tool built-in (WebFetch, Read, Write) — niente HTTP a mano, niente parsing
  • Programmatico ma sempre dentro l'ecosistema Anthropic: nessun pezzo di terze parti
  • Costo: solo $1-2/mese di API Claude (no piano Pro richiesto)

Quando NON sceglierlo

  • Se vuoi controllo byte per byte sul codice: meglio Anthropic SDK raw (Metodo B)
  • Se non vuoi installare nulla in locale: meglio Claude Code + Routines (Metodo A)
  • Se hai bisogno di un loop di chiamate altamente custom: il Metodo B è più flessibile

Architettura

⏰ cron / GitHub Actions → python team_agenti.py │ claude_agent_sdk.query( orchestrator + AgentDefinition x 4 ) │ 🧠 Orchestrator (Opus) usa il tool Agent │ ┌───────────────────┬───────────────────┐ ▼ ▼ ▼ pricing-watcher feature-watcher social-watcher (.md riusati dal Metodo A, ognuno coi suoi tool: WebFetch, ...) │ │ │ └───────────────────┼───────────────────┘ ▼ 🎯 synthesizer (Opus) → briefs/YYYY-MM-DD.md + mail

Quale scegliere

Tutti e 3 producono lo stesso brief, ogni mattina, in autonomia. Cambia solo da dove parti e come ti piace lavorare.

Scegli A Claude Code se

Sei già a tuo agio col terminale, hai il piano Claude Pro, e vuoi un sistema che vive interamente in Anthropic senza dipendere da nient'altro. È la scelta più pulita per chi è già "dentro" l'ecosistema e vuole zero codice.

Conosci Python e vuoi controllo totale a basso livello. È la scelta migliore se il sistema deve diventare un'API REST, finire in Docker, integrarsi col CI/CD aziendale, o se hai bisogno di logiche di orchestrazione molto custom che non si esprimono bene in un prompt.

Il Metodo B serve solo quando hai bisogno di scendere sotto il livello dell'SDK per logiche molto custom.

Oltre il competitor brief: come applicare il pattern

Il pattern che hai imparato — N ruoli specializzati + orchestrazione parallela + scheduling autonomo — vale per qualunque attività ricorrente che richiede di toccare più fonti e aggregare i risultati. Funziona in tutti e 3 i metodi: cambiano i ruoli e il config, il pattern resta.

  • 📰 Content radar settimanale — Ogni lunedì controlla blog di settore, newsletter, podcast trending. Output: 5 idee di contenuto per la settimana. Ruoli: blog-watcher, newsletter-watcher, podcast-watcher, idea-generator.
  • 🎯 Lead research automatica — Da una lista di aziende, per ognuna trova sito, settore, fatturato, decisionmaker LinkedIn, segnali di acquisto. Ruoli: company-profiler, financial-data-fetcher, decisionmaker-finder, signal-detector.
  • 📈 Account-based monitoring — Per i tuoi top 10 clienti: news, post social, hire recenti, segnali di rischio. Ruoli: news-watcher, social-watcher, hires-watcher, risk-summarizer.
  • 🏠 Real estate due diligence — Per ogni immobile: prezzo medio zona, trend, scuole, criminalità, lavori previsti. Ruoli: market-data-fetcher, neighborhood-profiler, public-records-checker, due-diligence-writer.
  • 🎙️ PR alert (menzioni brand) — Ogni mattina: menzioni su X, Reddit, Hacker News. Ti avvisa solo se trova qualcosa di rilievo. Ruoli: x-watcher, reddit-watcher, hn-watcher, alert-classifier.

Cambi i prompt dei ruoli, cambi il config, lasci uguale il pattern. Conosci il pattern, hai 5 sistemi diversi.
