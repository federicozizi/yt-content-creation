Cos'è una newsletter AI personale

Una newsletter normale è scritta da una persona, mandata a migliaia. Argomenti che spesso non ti interessano. Pubblicità in mezzo. Frequenza imposta. Tono imposto.

Una newsletter AI personale è scritta da Claude per te solo. Le fonti le scegli tu. La frequenza la scegli tu. Il tono lo scegli tu. Il filtro è il tuo cervello (espresso in 5 righe di istruzioni), non l'algoritmo di nessun social network.

Il punto: trasformi internet in un assistente che ogni mattina ti porta sulla scrivania solo le cose che contano per te. Niente browser aperti, niente notifiche, niente FOMO.

Caratteristiche del sistema:

  • Locale: gira sul tuo PC con Claude Code, niente cloud, niente upload di dati
  • Privato: nessuno vede le tue fonti né i tuoi riassunti
  • Modificabile in 30 secondi: cambi le fonti modificando un file JSON
  • Schedulabile: parte da solo ogni mattina con Claude Routines
  • Senza duplicati: Claude ricorda cosa ha già visto e non te lo ripropone

Cosa costruiremo oggi

Per dimostrare il pattern useremo un caso semplice e verificabile: una newsletter giornaliera sulle nuove uscite di Anthropic (la società che fa Claude). Ogni mattina alle 8, Claude visita la pagina news di Anthropic, identifica gli articoli usciti nelle ultime 24 ore, li riassume in 3-5 bullet ciascuno, e ti deposita un file markdown pulito sulla scrivania.

Esempio di come si presenta una newsletter prodotta:

# 🧠 La tua AI Brief — venerdì 16 maggio 2026 ## 3 novità Anthropic di oggi ### 🚀 Claude Sonnet 4.7 disponibile in beta - Aumento del 15% nelle prestazioni sui task di reasoning - Nuovo modello "thinking" attivabile su richiesta - Disponibile da subito su API e Claude.ai - 🔗 anthropic.com/news/claude-sonnet-4-7 ### 📄 Paper: "Constitutional AI v2" - Aggiornamento al sistema di principi alla base del training - Focus su trasparenza dei trade-off di sicurezza - 🔗 anthropic.com/research/constitutional-ai-v2 ### 🔧 Claude Code: nuova funzionalità "Plan Mode" - Modalità che separa pianificazione ed esecuzione - Utile per task complessi multi-step - 🔗 anthropic.com/news/plan-mode --- Generato in 47 secondi · 3 articoli letti · 2 articoli scartati (già visti)

Tu apri il file, leggi in 90 secondi, ne sai quanto chi passa 2 ore al giorno a seguire l'ecosistema. Fine.

L'esempio è "novità Anthropic", ma a fine video vedremo che lo stesso pattern funziona per qualunque sito: competitor, blog di settore, paper accademici, fonti di nicchia.

Come funziona il sistema

Solo 3 pezzi, tutti file di testo che modifichi con VS Code:

📁 LA CARTELLA "NEWSLETTER" (tutto qui dentro) ┌──────────────────────────────────────────────────────┐ │ │ │ 📝 fonti.json → "leggi questi siti" │ │ 📝 CLAUDE.md → "scrivi in questo tono" │ │ 📝 prompts/ → "ecco esattamente cosa fare" │ │ 📝 state.json → memoria: cosa ho già visto │ │ │ │ 📂 newsletter/ │ │ └── 2026-05-16.md ← l'output di oggi │ │ │ └──────────────────────────────────────────────────────┘ │ ▼ 🤖 CLAUDE CODE (lancia → visita siti → riassume → salva file) │ ▼ ⏰ CLAUDE ROUTINES (alle 8 di ogni mattina lo fa partire)

Claude Code ha già tutti gli strumenti che servono:

  • Web fetch: apre un URL e ne legge il contenuto. Built-in.
  • File write: scrive il file markdown. Built-in.
  • State tracking: usa state.json per ricordare cosa ha già processato. Lo aggiorna da solo.
  • Routines: il sistema di scheduling di Claude Code. Una riga per dirgli "fallo alle 8".

Niente Python, niente API key di servizi terzi, niente database. Solo Claude e file.

Setup iniziale

2 cose da preparare. Niente account complicati, niente carte di credito.

  1. Claude Code installato

    Su claude.com/code trovi sia l'app desktop (Mac/Windows/Linux, la via più semplice se non sei tech) sia le istruzioni per la CLI da terminale. Una volta installato, parte col tuo abbonamento Claude (Pro o Max) — niente API key da gestire. Se preferisci pagare a consumo, puoi usare una API key Anthropic.

    Dettagli tecnici — installazione CLI

    Se hai già Node.js (v18+):

    npm install -g @anthropic-ai/claude-code claude # primo login interattivo

    Se non hai Node.js, scarica la versione LTS da nodejs.org e rilancia. Su macOS con Homebrew: brew install node. Verifica con node --version e claude --version.

  2. Scarica i materiali

    La cartella allegata contiene tutto già configurato: fonti di esempio, prompt orchestratore, file di stato vuoto.

Il modo zero-stress: apri Claude Code dentro la cartella scaricata e digli "esegui il setup leggendo INIZIO_QUI.md". Fa le 3-4 verifiche, ti chiede 1-2 conferme, in 3 minuti il primo run è andato.

Step 1 — Definisci le fonti

Le fonti sono i siti che Claude visita ogni mattina. Nel nostro caso: le pagine di Anthropic dove escono le novità.

Il file fonti.json contiene una lista di URL con un'etichetta. Lo modifichi con VS Code. Aggiungi una fonte, ne togli una, in 10 secondi.

Esempio di fonti.json già pronto

{ "fonti": [ { "nome": "Anthropic News", "url": "https://www.anthropic.com/news", "categoria": "product" }, { "nome": "Anthropic Research", "url": "https://www.anthropic.com/research", "categoria": "research" }, { "nome": "Claude Code Changelog", "url": "https://docs.claude.com/en/release-notes/claude-code", "categoria": "changelog" } ] }

3 fonti di partenza. Una pagina news (annunci prodotti), una research (paper), un changelog (note di rilascio). Tre pezzi del puzzle "novità Anthropic".

Per aggiungere una fonte tua (es. un blog che ti interessa): aggiungi un blocco con nome, url, categoria. Niente sintassi strana, è un elenco.

File pronto: materiali/fonti.json.

Step 2 — Definisci il tono

Una newsletter sintetizzata male è peggio di nessuna newsletter. Se Claude scrive in modo prolisso, accademico, con paragrafi di 10 righe, non leggerai mai il file.

Il file CLAUDE.md al root della cartella dice a Claude come deve scrivere. Tono, lunghezza, struttura, cosa enfatizzare. Claude lo legge automaticamente all'avvio di ogni sessione.

Esempio di CLAUDE.md già pronto

## Tono della newsletter - Italiano, diretto, colloquiale - Max 3-5 bullet per articolo - Max 1 riga per bullet - Niente intro/outro generiche ("ecco le news di oggi…") - Niente aggettivi marketing ("rivoluzionario", "incredibile") - Sempre il link originale alla fine di ogni articolo ## Cosa enfatizzare - Numeri concreti (versioni, percentuali, prezzi) - Cosa cambia per chi usa il prodotto - Date di disponibilità ## Cosa scartare - Annunci di partnership senza dettagli concreti - Articoli "filler" (eventi sponsor, posizioni aperte) - Roba già coperta dai run precedenti (controlla state.json)

3 regole di tono, 3 cose da enfatizzare, 3 cose da scartare. È un foglio di istruzioni di 20 righe che vale per tutti i run futuri. Lo modifichi una volta, vale sempre.

File pronto: materiali/CLAUDE.md.

Step 3 — Lancia il primo run

Adesso fai partire Claude la prima volta e vedi cosa produce.

Un solo comando. Apri il terminale dentro la cartella materiali, digiti claude, e dai il prompt che trovi in prompts/newsletter-daily.md. Claude visita le fonti, identifica le novità, scrive la newsletter, aggiorna lo stato. ~1 minuto.

Cosa fare

  1. Apri Claude Code nella cartella
    cd materiali claude
  2. Dai il prompt

    Copia il contenuto di prompts/newsletter-daily.md e incollalo. Oppure di':

    esegui il prompt in prompts/newsletter-daily.md
  3. Aspetta ~1 minuto

    Claude ti racconta cosa sta facendo passo per passo: quale fonte sta leggendo, quali articoli ha trovato, quali ha scartato perché già visti. Trasparente.

  4. Apri il file generato

    Dentro newsletter/ trovi YYYY-MM-DD.md. Lo apri con VS Code o con qualsiasi reader markdown (es. Obsidian, Typora).

    📂 newsletter/ └── 2026-05-16.md ← ecco la tua prima newsletter

Se il risultato non ti piace, torna allo Step 2 e cambia il tono in CLAUDE.md. Rilancia. Si itera in 30 secondi.

Prompt orchestratore: materiali/prompts/newsletter-daily.md. Esempio di output: materiali/esempio-output.md.

Step 4 — Schedula con Claude Routines

Funziona, il primo run è andato. Adesso vogliamo che parta da solo ogni mattina, senza che tu apra il terminale.

Claude Routines è il sistema di scheduling integrato di Claude Code. Una riga per dire "alle 8 di ogni giorno, fai partire questo prompt in questa cartella". Niente cron, niente Task Scheduler di Windows, niente file YAML.

Cosa fare

  1. Crea la routine
    claude routines add daily-newsletter \ --schedule "0 8 * * *" \ --cwd "/path/to/materiali" \ --prompt "esegui prompts/newsletter-daily.md"

    Traduzione in italiano: "ogni giorno alle 8:00, entra in materiali e fai partire il prompt".

  2. Verifica
    claude routines list
    📋 Active routines: • daily-newsletter — every day at 08:00 — next: tomorrow 08:00
  3. Test manuale (per non aspettare fino a domattina)
    claude routines run daily-newsletter

    Forza l'esecuzione adesso. Se funziona, da domani parte da sola.

Da domani mattina, alle 8 trovi sempre un nuovo file in newsletter/. Tu non fai niente.

Alternativa se non hai Claude Routines: usa il Task Scheduler di Windows o cron su Mac/Linux. Lo script da lanciare è una riga: cd /path/to/materiali && claude --print "$(cat prompts/newsletter-daily.md)". Esempio completo in materiali/scheduling/crontab-example.txt.

Guida scheduling completa: materiali/scheduling/claude-routines.md.

Step 5 — Un team di agenti specializzati

Il sistema funziona. Tutte le mattine il file arriva. Ma fa sempre la stessa cosa: legge le fonti, riassume. Punto.

Adesso lo rendiamo intelligente. Aggiungiamo 2 piccoli agenti specializzati che si attivano automaticamente quando serve, senza che tu debba pensarci.

L'idea: l'orchestratore principale fa il lavoro standard (fetch + riassunto). Quando incontra casi speciali — giornata senza novità, oppure un major update da segnalare — chiama in automatico un agente specializzato in quel caso specifico. Tu vedi solo il risultato finale: una newsletter più ricca, più utile, più affidabile.

Chi sono i 2 agenti

🚑 empty-day-rescue Si attiva quando l'orchestratore finisce il run senza aver trovato nessun articolo nuovo nelle ultime 48 ore. Invece di lasciarti il file vuoto, va su fonti secondarie definite a parte (tweet ufficiali di Anthropic, podcast AI, blog di founder che hai segnalato) e pesca 1-2 contenuti di approfondimento — anche se non sono "novità" stretto senso. Risultato: zero giornate vuote.
🚨 major-update-spotter Si attiva SEMPRE alla fine del run, sui risultati appena prodotti. Classifica ogni articolo per importanza e se trova un major update — un nuovo modello rilasciato, un nuovo prodotto/tool/servizio, un breaking change importante — lo evidenzia in cima al file con un box rosso 🚨 MAJOR UPDATE e ti suggerisce 1-2 azioni concrete (es. "prova il modello su Claude.ai", "leggi l'announcement post"). Risultato: le notizie che contano non si perdono in mezzo a quelle minori.

Come funziona il team

🤖 ORCHESTRATOR (prompts/newsletter-daily.md) │ "leggi fonti, riassumi novità" │ ├──── 0 risultati? ─── SÌ ──▶ 🚑 empty-day-rescue │ (cerca su fonti secondarie) │ ▼ 📄 newsletter/YYYY-MM-DD.md │ ▼ 🚨 major-update-spotter (rilegge il file, mette in cima i major update) │ ▼ 📄 newsletter/YYYY-MM-DD.md ← arricchito

Gli agenti vivono come file di testo in .claude/agents/. Claude Code li riconosce in automatico — non devi configurare nient'altro.

Cosa fare

  1. I 2 file degli agenti

    Sono già nei materiali, in .claude/agents/empty-day-rescue.md e .claude/agents/major-update-spotter.md. Sono file Markdown con un piccolo header YAML che dice a Claude Code: "questo è un sub-agent, si chiama X, fa Y, può usare questi tool".

    --- name: empty-day-rescue description: Si attiva quando la newsletter del giorno è vuota. Cerca contenuti di approfondimento su fonti secondarie. tools: [web_fetch, file_write] --- Sei un agente di "rescue" per la newsletter giornaliera. Quando l'orchestratore ti chiama, hai 0 articoli nuovi nelle fonti primarie. Vai sulle fonti elencate in `fonti-fallback.json` e ... [regole complete dentro il file]
  2. La lista delle fonti secondarie

    L'agente empty-day-rescue ha bisogno di sapere DOVE andare quando le fonti primarie sono vuote. Il file fonti-fallback.json contiene questa lista — già pronto con 3 esempi (Anthropic on X, blog di Dario Amodei, Latent Space podcast). Lo modifichi col tuo VS Code se vuoi cambiare le fonti di backup.

  3. L'orchestratore aggiornato

    Il file prompts/newsletter-daily.md include ora 2 nuove righe alla fine: "se ho trovato 0 articoli, chiama empty-day-rescue. In ogni caso, alla fine, chiama major-update-spotter sul file appena salvato." Niente codice, sono istruzioni in italiano. Claude Code interpreta e delega.

  4. Test

    Rilancia il prompt come hai fatto nello Step 3:

    claude --print "$(cat prompts/newsletter-daily.md)"

    Vedi che ora Claude, nei suoi step, dice cose come "chiamo major-update-spotter…" e nel file di output trovi (se c'è davvero un major update di oggi) un box in cima così:

    ## 🚨 MAJOR UPDATE — Claude Sonnet 4.7 disponibile in beta > Nuovo modello con +15% performance reasoning. Disponibile ora su API e Claude.ai. > **Cosa fare**: provalo su claude.ai/new e confronta con 4.6 sul tuo task ricorrente più impegnativo. --- [poi segue la newsletter normale...]

Quando questo sistema fa davvero la differenza

  • Nei weekend e festivi: Anthropic e altre aziende pubblicano poco. Senza empty-day-rescue avresti file vuoti, ti dimenticheresti del sistema. Con lui, hai sempre qualcosa da leggere.
  • Sui major release: senza major-update-spotter, un lancio importante può finire sepolto tra 5 articoli minori e ti scappa. Con lui, è la prima cosa che vedi quando apri il file.
  • Per scalare il sistema: domani vuoi aggiungere un terzo agente (es. "traduttore", "extractor di codice", "fact-checker")? Crei un nuovo file in .claude/agents/ con la sua descrizione, dici all'orchestratore quando chiamarlo, fine. Il pattern si estende all'infinito.
Sub-agent vs single big prompt: avresti potuto mettere tutta questa logica dentro l'orchestratore principale (un unico mega-prompt che fa fetch + summary + fallback + classifica + spotting). Funzionerebbe, ma diventerebbe ingestibile in fretta. Separare in sub-agent specializzati ha 3 vantaggi: 1) chiarezza (ogni file fa una cosa sola), 2) riusabilità (il major-update-spotter domani lo riusi anche su un'altra newsletter, basta copiare un file), 3) debugging (se qualcosa non va, sai esattamente quale agente toccare).

File degli agenti: materiali/.claude/agents/empty-day-rescue.md · materiali/.claude/agents/major-update-spotter.md. Fonti fallback: materiali/fonti-fallback.json.

Oltre Anthropic: come applicare il pattern

L'esempio "novità Anthropic" è uno dei mille modi in cui questo sistema si combina. Cambi 2 file (fonti.json e CLAUDE.md), e Claude lavora per un altro caso. Stessa cartella, stesso prompt, stesso scheduling.

Newsletter competitor In fonti.json metti i siti dei tuoi 3 competitor (pagine blog, news, changelog). In CLAUDE.md dici "enfatizza prezzi, lanci di prodotto, mosse strategiche". Ogni mattina sai cosa fanno senza aprire LinkedIn.
Newsletter di settore B2B Fonti: 5-10 blog/testate del tuo settore (es. fintech: Sifted, Finextra, EU-Startups; legal: Legalweek, Above the Law). Tono: "linguaggio tecnico, italiano, enfasi su deal e regolamentazione". 10 minuti di lettura sostituiscono 2 ore di scroll.
Newsletter di paper accademici Fonti: arXiv categorie selezionate (es. cs.AI, cs.CL), Google Scholar Alerts. Tono: "spiega in modo accessibile, includi link al paper PDF". Resti al passo con la ricerca senza dover leggere abstract criptici.
Newsletter di trend social (consulenti, agenzie) Fonti: account LinkedIn di top voice del tuo settore (via pagine pubbliche). Tono: "estrai le opinioni forti dell'ultima settimana, max 3 per persona". Capisci di cosa parla il tuo mondo professionale senza vivere su LinkedIn.
Newsletter "clipping" per ufficio stampa / PR Fonti: testate che potrebbero menzionare il tuo brand. In CLAUDE.md: "scarta tutto, riportami solo articoli che contengono la parola 'XXX' (il mio brand) o 'YYY' (i miei prodotti)". Brand monitoring fatto in casa, gratis, ogni mattina.

Il pattern: fonti + tono + state tracking + scheduling. Cambia solo cosa metti in fonti.json e in CLAUDE.md. Il resto è identico.
