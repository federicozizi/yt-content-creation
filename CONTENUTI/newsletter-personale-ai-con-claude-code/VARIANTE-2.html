Cos'è una newsletter AI personale

Una newsletter AI personale è scritta da Claude per te solo. Fonti tue, tono tuo, frequenza tua. Il filtro è il tuo cervello (5 righe di istruzioni), non l'algoritmo di nessun social.

Cosa cambia in questa variante: niente Claude Code, niente Agent SDK. Solo uno script Python ~80 righe che fa esplicitamente tutti i passaggi: scarica HTML/RSS delle fonti, parsea per estrarre articoli nuovi, scarica i full text, manda a Claude solo i testi puliti per il riassunto, salva il markdown.

L'idea è la massima trasparenza: ogni pezzo è codice tuo, leggibile, debuggabile. Se domani Claude API è giù, sai esattamente dove sostituire il pezzo. Se vuoi cambiare il parser HTML, sai dove mettere le mani.

Costo: ridotto al minimo (Claude vede solo il testo già estratto, non deve fare lui il web fetching — risparmi token).

Flusso dello script, passo passo:

  1. requests scarica l'HTML di ogni fonte
  2. BeautifulSoup estrae lista articoli (titolo + URL + data)
  3. Filtro Python: tieni solo articoli nuovi (non in state.json) e recenti (≤48h)
  4. Per ogni articolo nuovo, requests scarica il full HTML, BeautifulSoup estrae il body
  5. anthropic SDK chiama l'API col prompt di sintesi + il testo estratto
  6. Componi markdown finale, scrivi in newsletter/YYYY-MM-DD.md
  7. Aggiorna state.json

Zero agent loop, zero tool use, zero magia. Codice procedurale leggibile.

Step 1 — Definisci le fonti (HTML o RSS)

Lo schema di fonti.json qui supporta 2 tipi di fonte:

{ "fonti": [ { "nome": "Anthropic News", "url": "https://www.anthropic.com/news", "tipo": "html", "selettore_articolo": "article a[href*='/news/']", "categoria": "product" }, { "nome": "Hacker News (front page)", "url": "https://hnrss.org/frontpage", "tipo": "rss", "categoria": "tech" } ] }

Per le fonti html serve un selettore CSS che identifica i link agli articoli (semplice da scoprire con DevTools del browser: tasto destro → Ispeziona → individui il pattern dei link agli articoli, copi il selettore CSS).

Per le fonti rss niente selettore: feedparser fa tutto in automatico.

Vantaggio RSS quando disponibile: stabilità garantita (il sito può cambiare layout senza rompere il tuo parser). Quando un sito espone RSS, preferiscilo sempre.

Step 2 — Il prompt di sintesi

In questa variante il tono vive in prompt.txt (semplice file di testo, non Markdown speciale). Lo script lo legge una volta e lo passa nel system prompt dell'API call.

Sei un assistente che riassume articoli per una newsletter personale. REGOLE TONO: - Italiano, diretto, colloquiale - Max 3-5 bullet per articolo, max 1 riga ciascuno - Niente intro/outro, niente aggettivi marketing ENFATIZZA: - Numeri concreti, date, breaking changes - Cosa cambia per chi usa il prodotto SCARTA: - Filler, partnership senza dettagli concreti - Posizioni aperte, eventi sponsor OUTPUT: solo i bullet del riassunto, niente titolo (lo aggiunge lo script).

Lo script chiama l'API una volta per articolo, passando solo il testo estratto + questo prompt. Nessun loop agent, nessun tool, nessuna ambiguità.

File pronto: materiali-variante-2/prompt.txt.

Step 3 — Lo script newsletter.py

~80 righe di Python che leggi e capisci dall'inizio alla fine.

Filosofia: ogni passaggio è una funzione Python con nome chiaro. fetch_sources(), extract_articles(), summarize_article(), compose_newsletter(). Apri lo script, leggi i 4 nomi, hai capito il flusso.

Estratto delle funzioni chiave

def extract_articles(fonte: dict) -> list[dict]:
    """Scarica la fonte e ritorna lista di articoli {title, url, date}."""
    if fonte["tipo"] == "rss":
        feed = feedparser.parse(fonte["url"])
        return [{"title": e.title, "url": e.link, "date": e.published} for e in feed.entries]
    elif fonte["tipo"] == "html":
        html = requests.get(fonte["url"], timeout=15).text
        soup = BeautifulSoup(html, "html.parser")
        return [
            {"title": a.text.strip(), "url": urljoin(fonte["url"], a["href"])}
            for a in soup.select(fonte["selettore_articolo"])
        ]


def summarize_article(articolo: dict, prompt_sintesi: str) -> str:
    """Scarica il full text dell'articolo e chiama Claude per riassumere."""
    full_html = requests.get(articolo["url"], timeout=15).text
    text = BeautifulSoup(full_html, "html.parser").get_text(" ", strip=True)[:8000]

    msg = client.messages.create(
        model=os.getenv("ANTHROPIC_MODEL", "claude-sonnet-4-7"),
        max_tokens=400,
        system=prompt_sintesi,
        messages=[{"role": "user", "content": f"Articolo:\n\n{text}"}],
    )
    return msg.content[0].text

Lo script reale gestisce errori (timeout, 404), filtri sui duplicati, scrittura atomica del file. Ma il cuore è questo: scarica → estrai → riassumi → componi.

Oltre Anthropic: come applicare il pattern

Tutti i 5 use case dei metodi precedenti funzionano qui. Il vantaggio di questa variante: hai accesso a ogni byte del flusso.

Filtri pre-Claude super-aggressivi Prima di chiamare l'API, filtri brutalmente in Python (es. tieni solo articoli con almeno 3 keyword del tuo settore nel body). Mandi a Claude 1 articolo su 20 → costi ridotti a centesimi/mese.
Pipeline AI multi-stage Step 1: chiami Claude con un modello piccolo (Haiku, $0.0003/articolo) per classificare se l'articolo merita o no. Step 2: solo gli articoli "approvati" passano a Sonnet per il riassunto vero. Risparmi 70% di token usando Claude in cascata.
Caching aggressivo Nello script Python aggiungi una cache su disco degli articoli scaricati (se l'URL è già stato scaricato negli ultimi 7 giorni, riusi). Riduci traffico web e tempo di esecuzione.
Multi-output Lo stesso run produce: 1) la newsletter markdown, 2) un POST per LinkedIn (200 caratteri), 3) una entry in un database SQLite per ricerca future. 1 chiamata Claude, 3 output diversi.
