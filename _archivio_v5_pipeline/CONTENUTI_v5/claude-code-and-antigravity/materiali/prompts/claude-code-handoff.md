# Prompt for Claude Code — handoff from the Antigravity artifact

This prompt is used **locally**, by running `claude` inside your real site folder (not inside the video materials folder).

## When to use it

After you have:
1. Generated 3 variants in Antigravity (with the `antigravity-parallel-draft.md` prompt).
2. Picked the best one.
3. Downloaded the artifact as `_from_antigravity/landing-winner.html` in your site folder.

## Setup

```
# 1. Go into your site folder
cd ~/path/to/your-site

# 2. Verify you have:
#    - index.html (the current home)
#    - _from_antigravity/landing-winner.html (the chosen artifact)

# 3. Run Claude Code
claude
```

## PROMPT to paste

```
I need to integrate an Antigravity artifact into my real site. Proceed like this:

CONTEXT:
- The index.html in this folder is the current home of my site (with my internal links, meta tags, assets, possibly tracking scripts).
- The file _from_antigravity/landing-winner.html is the new home generated by an Antigravity agent in the cloud. Visually nice but disconnected from my project: it uses made-up links, may have renamed files, doesn't know my meta tags.

GOAL:
Produce a NEW index.html that takes the design and copy from the artifact, but respects ALL the context of the real site.

MERGE RULES:

1. From the new (landing-winner.html), take:
   - Visual structure, palette, typography
   - Section copy (headlines, subheads, paragraphs, claims)
   - Any new semantic blocks (e.g. a "testimonial" section if there wasn't one before)

2. From the old (index.html), ALWAYS preserve:
   - All internal links with real href (e.g. "/about", "/services/consulting", "/contact")
     → if the artifact has href="#" or invented ones for the same labels, replace with the old ones
   - The meta tags in <head>: title, description, OpenGraph, Twitter card, canonical
   - Existing asset paths (images, external CSS, favicon) — if the artifact references assets that don't exist in my repo, flag it and propose one of:
     (a) swap with an existing equivalent asset
     (b) keep the reference and tell me which file I need to add
   - Tracking scripts, analytics, pixels, tag manager
   - The lang attribute of the <html> element

3. Edge cases:
   - If the new has a 5-item menu and the old had 3, keep the 3 from the old (with their href) and add the 2 new ones with href="#", flagging them to me.
   - If the new imports Google Fonts via CDN, REMOVE that import (project rule: no external CDN) and replace with similar system fonts.

PROCESS:
1. Read both files.
2. Build the merge in a markdown block — DON'T overwrite index.html yet.
3. Show me:
   (a) the synthetic diff (what changes vs current index.html)
   (b) the list of decisions you made on edge cases (links swapped, assets flagged, etc.)
4. Wait for my explicit OK.
5. After OK:
   - Overwrite index.html with the merged version
   - If this folder is a git repo, commit with message: `feat: refresh home (variant <style> from Antigravity)`
   - Move _from_antigravity/landing-winner.html to _from_antigravity/_archive/ renaming with the date (e.g. landing-winner-2026-05-18.html)
   - If _from_antigravity/ has other discarded variants (e.g. landing-corporate.html, landing-aggressive.html), move them to _archive/ as well

Go.
```

## What to expect

- Claude Code reads the two files and produces the diff: typically 2-5 minutes if the site is simple (a home around ~300 lines).
- The diff includes both the code changes and the "edge case" decisions (swapped links, flagged assets).
- You approve (or ask for targeted fixes before approving).
- The final commit is clean, a single atomic change.

## If something goes wrong

- "The artifact imports Google Fonts and Claude removed them, now the fonts look bad" → tell it: "put them back as a fallback, but use font-family system-ui first, Inter second".
- "It replaced an internal link it shouldn't have" → flag the specific link and say: "restore /about-us to original, keep /who-we-are only if it appears in the new as a different label".
- "I want to see the diff more visually" → tell it: "show it as `git diff --color`".
