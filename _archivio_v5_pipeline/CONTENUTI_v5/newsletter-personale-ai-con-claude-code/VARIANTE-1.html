Cos'è una newsletter AI personale

Una newsletter AI personale è scritta da Claude per te solo. Le fonti le scegli tu. La frequenza la scegli tu. Il tono lo scegli tu. Il filtro è il tuo cervello (espresso in 5 righe di istruzioni), non l'algoritmo di nessun social network.

Cosa cambia in questa variante: invece di lanciare Claude Code da terminale, scrivi uno script Python che usa Claude Agent SDK — la libreria ufficiale che permette di creare agenti Claude programmaticamente. Lo script gira come qualunque altro script Python: lo lanci con python newsletter.py, lo schedule con cron.

Il risultato finale è identico al metodo principale: un file markdown in newsletter/YYYY-MM-DD.md. Quello che cambia è il controllo: hai accesso al codice intermedio, puoi aggiungere logica custom prima/dopo la generazione, puoi cambiare ogni pezzo.

Cosa costruiremo oggi

Lo stesso esempio del metodo principale: una newsletter giornaliera sulle nuove uscite di Anthropic. Ogni mattina alle 8, lo script Python visita la pagina news, identifica gli articoli nuovi, li riassume in markdown.

L'output è identico a quello del metodo principale (stesso layout, stesso stile). Quello che cambia è come arriva al risultato.

# 🧠 La tua AI Brief — venerdì 16 maggio 2026 ## 3 novità di oggi ### 🚀 Claude Sonnet 4.7 disponibile in beta - Aumento del 15% nelle prestazioni sui task di reasoning - ... [output identico al metodo principale]

Come funziona il sistema

📁 LA CARTELLA "NEWSLETTER" (Python project) ┌──────────────────────────────────────────────────────┐ │ │ │ 📝 newsletter.py → lo script Agent SDK │ │ 📝 fonti.json → "leggi questi siti" │ │ 📝 CLAUDE.md → "scrivi in questo tono" │ │ 📝 state.json → memoria URL già visti │ │ 📝 requirements.txt → claude-agent-sdk, ecc. │ │ 📝 .env → ANTHROPIC_API_KEY │ │ │ │ 📂 newsletter/ │ │ └── 2026-05-16.md ← output di oggi │ │ │ └──────────────────────────────────────────────────────┘ │ ▼ 🐍 python newsletter.py (script che usa Claude Agent SDK come libreria) │ ▼ ⏰ cron / Task Scheduler (alle 8 di ogni mattina parte da solo)

I pezzi nuovi rispetto al metodo principale:

  • newsletter.py: ~50 righe di Python. Crea un Agent Claude, gli dà i tool (WebFetch), gli passa il prompt, salva l'output.
  • .env: contiene la tua API key Anthropic (l'SDK ne ha bisogno).
  • requirements.txt: lista dei pacchetti Python (claude-agent-sdk, python-dotenv).

Il file CLAUDE.md col tono e fonti.json con le fonti restano identici al metodo principale. Stessa filosofia, stesso pattern.

    Costo: ~$0.01-0.05 per run (la newsletter usa ~5k token in input + ~2k in output). Per un run al giorno → ~$0.30-1.50/mese.

Step 1 — Definisci le fonti

Identico al metodo principale. Il file fonti.json ha la stessa struttura.

{ "fonti": [ {"nome": "Anthropic News", "url": "https://www.anthropic.com/news", "categoria": "product"}, {"nome": "Anthropic Research", "url": "https://www.anthropic.com/research", "categoria": "research"}, {"nome": "Claude Code Changelog", "url": "https://docs.claude.com/en/release-notes/claude-code", "categoria": "changelog"} ] }

Lo script Python lo legge con json.load() e lo passa al prompt dell'Agent.

Step 2 — Tono in CLAUDE.md + prompt embedded

In questa variante il tono vive in CLAUDE.md (esattamente come nel metodo principale) MA viene passato esplicitamente al prompt dello script. L'Agent SDK non legge automaticamente CLAUDE.md come fa Claude Code CLI — devi caricarlo tu.

Differenza chiave: con Claude Code CLI il file CLAUDE.md viene caricato in automatico ad ogni sessione. Con l'Agent SDK lo carichi tu nel codice (open("CLAUDE.md").read()) e lo concateni al prompt di sistema. È un passaggio in più, ma ti dà controllo totale su cosa passi al modello.

File pronto: materiali-variante-1/CLAUDE.md.

Step 3 — Lo script newsletter.py

Il cuore della variante. ~50 righe di Python che fanno il lavoro.

Struttura dello script: 1) carica fonti, stato, tono; 2) crea l'Agent col tool WebFetch attivo; 3) passa il prompt; 4) salva l'output nel file giusto; 5) aggiorna state.json.

Esempio (versione semplificata)

from claude_agent_sdk import Agent, tool_use
from datetime import datetime
import json, os
from pathlib import Path
from dotenv import load_dotenv

load_dotenv()

ROOT = Path(__file__).parent
fonti = json.loads((ROOT / "fonti.json").read_text())
state = json.loads((ROOT / "state.json").read_text())
tono = (ROOT / "CLAUDE.md").read_text()

agent = Agent(
    model="claude-sonnet-4-7",
    system=f"Sei un assistente che genera newsletter giornaliere.\n\n{tono}",
    tools=["web_fetch"],
)

prompt = f"""
Genera la newsletter di oggi.

Fonti: {json.dumps(fonti)}
Articoli gia visti (da non riproporre): {json.dumps(state["articoli_visti"])}

Salva il risultato in newsletter/{datetime.now().strftime("%Y-%m-%d")}.md
Aggiorna state.json con gli URL processati oggi.
"""

result = agent.run(prompt)
print(result.summary)

Lo script reale nei materiali è leggermente più strutturato (gestione errori, logging, controllo se la cartella newsletter/ esiste), ma il cuore è questo: Agent Claude + tool WebFetch + il tuo prompt = newsletter generata.

Script completo: materiali-variante-1/newsletter.py.

Step 4 — Schedula con cron (o Task Scheduler)

Niente Claude Routines qui: stai usando uno script Python normale, quindi lo schedule come qualunque altro script.

Su Mac/Linux

crontab -e

Aggiungi una riga:

0 8 * * * cd /path/to/materiali-variante-1 && /path/to/.venv/bin/python newsletter.py >> /tmp/newsletter.log 2>&1

Traduzione: "ogni giorno alle 8:00, entra nella cartella, attiva il venv, lancia lo script, salva i log".

Su Windows

Utilità di pianificazione → Crea attività → Trigger giornaliero ore 8:00 → Azione "Avvia programma":

  • Programma: C:\path\to\materiali-variante-1\.venv\Scripts\python.exe
  • Argomenti: newsletter.py
  • Inizio in: C:\path\to\materiali-variante-1
Vantaggio cron vs Claude Routines: cron gira anche su server headless senza Claude Code installato. Se domani vuoi spostare il sistema su un VPS da $5/mese che resta sempre acceso, basta copiare la cartella e configurare cron. La newsletter arriva anche col tuo PC spento.

Esempi completi: materiali-variante-1/scheduling/crontab-example.txt.

Oltre Anthropic: come applicare il pattern

Tutti i 5 use case del metodo principale funzionano identici qui. Il vantaggio di questa variante è che puoi aggiungere logica custom direttamente nello script Python.

Filtro pre-Claude Prima di passare le fonti all'Agent, filtri tu in Python (es. tieni solo articoli con certe keyword nel titolo). Risparmi token e velocizzi il run.
Multi-destinatari Generi la newsletter una volta, poi nello script Python la duplichi adattandola per pubblici diversi (es. una versione "tech" e una "business"). 2 file output, 1 chiamata Claude.
Scrittura su database / Notion / Airtable Dopo aver generato il markdown, lo script Python lo salva anche su Notion API o Airtable API. La newsletter è un layer sopra; il dato resta strutturato altrove.
Trigger non-tempo-based Invece di cron, fai partire lo script quando arriva una webhook (es. "ogni volta che qualcuno apre una issue su un repo X, genera mini-brief"). Lo script Python si integra ovunque, cron è solo una delle opzioni.
Team di sub-agent specializzati Lo stesso pattern empty-day-rescue + major-update-spotter del metodo principale (Step 5) qui si replica in Python: 2 istanze Agent() aggiuntive nello script, una per ruolo, ognuna con il suo system prompt. Le chiami in cascata dentro newsletter.py dopo l'Agent principale. Vantaggio rispetto al metodo CLI: puoi orchestrare il flow con logica Python esplicita (es. "se 0 risultati AND giorno feriale, chiama solo rescue; weekend, chiama anche un terzo agent 'weekly-digest'").
