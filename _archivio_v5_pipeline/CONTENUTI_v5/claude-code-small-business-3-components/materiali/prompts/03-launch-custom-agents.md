# Prompt 03 — Launching custom agents via Agent View

This step happens in **Claude Code** inside the `materiali/` folder. Launches the firm's custom agents in parallel.

## Prerequisites

- Step 1 done (Supabase MCP working).
- Step 2 ideally done, but not required: the custom agents work on Supabase independently of the Anthropic package.

## Setup

```bash
cd materiali
claude
```

And paste:

```
Let's see the custom agents in action. Before launching them, I want to know
what's there.

STEPS:

1. List the sub-agents
   - List files in .claude/agents/ with their name (from frontmatter) and
     description (also from frontmatter).
   - Expected: document-classifier, regime-checker, deadline-alerter.

2. Open Agent View
   - Tell the user: "Now I'll show you the dashboard. Open it yourself in
     another terminal with the command: claude agents. You'll see the 3
     agents listed, each in 'ready' state. From there you could launch them
     with a click. Instead I'll launch them directly from this session so
     you see the output."
   - Confirm the user has seen the dashboard (or accept skipping and proceed
     via this session).

3. Launch regime-checker (simplest and fastest to see in action)
   - Run the instructions in .claude/agents/regime-checker.md.
   - Use the Supabase MCP connector for the query on the
     v_clients_near_limit view.
   - For each client found, do the INSERT into internal_notes as per the
     sub-agent's instructions.
   - Show the user: how many rows the view returned, how many alerts you
     generated, how many you skipped to avoid duplicates in the last 7 days.

4. (Optional) Launch deadline-alerter in parallel
   - If the user wants to see parallelism: launch deadline-alerter "in queue"
     after regime-checker (sub-agents in Claude Code are async but not true
     parallel threads when launched from CLI; for true parallelism use the
     `claude agents` dashboard or the Task tool).
   - Show the markdown report generated in logs/deadlines-YYYY-MM-DD.md.

5. document-classifier — save for when you have real documents
   - Tell the user: "document-classifier needs documents uploaded by clients
     in Drive (connected via the Small Business package). To test it in
     simulation, you can hand it text from a fake invoice. But its real use
     is in production, when the Anthropic package notifies you 'file arrived
     from client X', you trigger document-classifier on that file. See
     prompts/04-end-to-end-integration.md for the full flow."

6. Show what happened
   - Run a Supabase query to read internal_notes from the last 5 minutes,
     ordered by created_at DESC. Show the new rows generated by the agents.
   - Expected: some rows with author = 'agent:regime-checker' or
     'agent:deadline-alerter'.

RULES:

- Don't modify sub-agent files during execution. If you see a bug in the
  instructions, stop and flag it to the user.
- Don't launch the agents more than once per session without permission —
  otherwise you risk duplicating alerts (even though the sub-agents'
  instructions handle deduplication, better be explicit).
- Don't perform external actions (emails, files uploaded elsewhere, etc.) —
  custom sub-agents write ONLY to Supabase.

Go.
```
