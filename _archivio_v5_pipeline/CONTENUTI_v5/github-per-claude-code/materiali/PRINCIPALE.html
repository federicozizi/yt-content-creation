Cos'è GitHub

GitHub è una piattaforma online dove tieni cartelle di progetto (si chiamano "repo"). Ogni modifica salvata resta nello storico, puoi condividerle, puoi avere versioni parallele dello stesso progetto. È gratis fino a 2.000 minuti/mese di automazioni sui repo privati. Sui repo pubblici è gratis e illimitato.

Le 4 cose di GitHub che ci servono:

  • Repo: la cartella di progetto online
  • Issue: post-it digitali con dei task
  • Pull request: proposte di modifica al progetto, da approvare prima che entrino davvero
  • Actions: automazioni che girano su un computer di GitHub agli orari o eventi che decidi tu
Il punto: tu hai bisogno di un posto per dare istruzioni a Claude, schedulare quando deve girare, vedere lo storico, e revisionare il suo lavoro. GitHub fa tutte queste cose, è gratis, e Claude Code ci si infila come esecutore.

Cosa costruiremo oggi

Useremo come esempio lo stesso sistema del video precedente: un brief sui 3 competitor che ogni mattina alle 7 ti arriva pronto (prezzi, annunci, post LinkedIn).

La differenza: stavolta gira da solo in cloud. Tu non lanci niente. Apri il telefono alle 8, GitHub ti notifica che il brief è pronto, lo leggi, lo approvi. 30 secondi.

07:05 di ogni mattina │ ▼ GitHub avvia Claude in cloud │ ▼ Claude visita pricing, blog, LinkedIn di ogni competitor sintetizza il brief in 400 parole │ ▼ Apre una pull request col file del brief │ ▼ Tu ricevi notifica → leggi → approvi

Costo: pochi centesimi al giorno (~$0.30-1.50/mese di API Anthropic). GitHub Actions gratis. L'esempio è il brief competitor, ma a fine video vedremo che gli stessi 5 trucchi funzionano per qualunque flusso ricorrente.

Setup iniziale

4 cose da preparare:

  1. Account GitHub gratuito

    github.com/signup. Email + password. Nessun upgrade richiesto.

  2. Claude Code installato

    Su claude.com/code trovi sia l'app desktop (Mac/Windows/Linux, la via più semplice se non sei tech) sia le istruzioni per la CLI da terminale. Funziona col tuo abbonamento Claude (Pro o Max) oppure con una API key Anthropic se preferisci pagare a consumo.

    Dettagli tecnici — installazione CLI

    Se hai già Node.js (v18+):

    npm install -g @anthropic-ai/claude-code claude # primo login interattivo

    Se non hai Node.js, scarica la versione LTS da nodejs.org e rilancia. Su macOS con Homebrew: brew install node. Verifica con node --version e claude --version.

  3. Chiave API Anthropic

    Serve perché GitHub possa "chiamare" Claude in cloud. Vai su console.anthropic.com → Settings → API Keys → Create Key. Copia la chiave (inizia con sk-ant-...).

  4. Scarica i materiali

    La cartella allegata contiene tutto già configurato.

Il modo zero-stress: apri Claude Code dentro la cartella scaricata e digli "esegui il setup leggendo INIZIO_QUI.md". Crea il repo, imposta la chiave API, fa il primo test. Tu rispondi a 2-3 domande. 5 minuti.
Approfondimento tecnico — comandi a mano
cd materiali gh repo create my-claude-repo --private --source . --push gh secret set ANTHROPIC_API_KEY # incolla la chiave gh workflow run daily-brief.yml # primo test

Trucco 1 — Memoria persistente: regole una volta, valgono per sempre

Ogni nuova sessione di Claude Code parte da zero. Non sa che vuoi output in italiano, non sa il tuo tone-of-voice, non sa quali file non deve toccare. Glielo ripeti ogni volta.

Soluzione: metti un file chiamato CLAUDE.md al root del repo. Claude Code lo legge automaticamente all'avvio di ogni sessione. Scrivi le regole una volta, valgono sempre — anche per le sessioni che girano in cloud.

Cosa risolve

  • Smetti di ripetere convenzioni a ogni sessione
  • Se lavori in team, tutti i colleghi (e i loro Claude) seguono le stesse regole
  • Vale anche per le esecuzioni schedulate (Trucco 3) e le issue automatiche (Trucco 4)

Cosa metterci dentro

Esempio dal nostro repo:

## Convenzioni - Lingua output: italiano - Brief: markdown, max 400 parole - Niente segreti committati (vivono in GitHub Secrets) - Branch: auto/<data>-<slug>, mai diretto su main - Stile: diretto, asciutto ## File chiave | File | Quando toccarlo | |---|---| | competitors.json | Quando cambi competitor | | prompts/daily-brief.md | Solo se cambi struttura brief | | .github/workflows/* | Solo se cambi cron o trigger |

È un file di testo. Lo modifichi con VS Code. Lo salvi nel repo. Da quel momento, ogni Claude Code che entra nel repo conosce queste regole prima di iniziare.

Esempio già compilato: materiali/CLAUDE.md.

Trucco 2 — 3 Claude in parallelo (senza pestarsi i piedi)

Hai 3 task indipendenti da fare oggi. Una alla volta perdi tempo. Tre Claude nella stessa cartella si pestano i piedi (modificano gli stessi file).

Soluzione: git worktree. Crea 3 sottocartelle, ognuna è una copia indipendente del progetto su un branch diverso. Ogni Claude lavora nella sua sottocartella. L'originale (main) resta intoccato finché non scegli cosa salvare.

Cosa risolve

  • Triplichi la velocità nei giorni con più task indipendenti
  • Puoi provare 2 versioni della stessa modifica in parallelo, scegli quella migliore, butti l'altra
  • Sperimenti senza rischi: se un Claude prende una direzione che non ti piace, rimuovi la sottocartella e tutto sparisce

Come si fa

  1. Crei le 3 sottocartelle
    git worktree add .worktrees/aggiungi-delta -b feat/delta git worktree add .worktrees/cambia-modello -b feat/modello git worktree add .worktrees/fix-linkedin -b fix/linkedin

    Ognuna è una copia del progetto su un branch dedicato.

  2. Apri 3 Claude Code (3 finestre Desktop)

    In ognuna entri in una sottocartella e dai il task:

    cd .worktrees/aggiungi-delta claude > aggiungi Delta Corp ai competitor (sito: delta.example.com)
  3. Aspetti che finiscano

    I 3 Claude lavorano in parallelo, ognuno sulla sua copia.

  4. Decidi cosa tenere

    Risultato che ti convince → apri pull request. Risultato che non ti convince → rimuovi la sottocartella, sparisce tutto.

    cd .worktrees/aggiungi-delta gh pr create --fill

Pattern completo: materiali/docs/worktree-pattern.md.

Trucco 3 — Lavoro schedulato in cloud (anche col PC spento)

Vuoi un report ogni mattina alle 7. Non puoi tenere il PC acceso tutta la notte. Cron locale non basta.

Soluzione: GitHub Actions. Una "ricetta" YAML che dice a GitHub "alle 7:05 di ogni giorno, prendi questo repo, installa Claude Code, fagli eseguire il prompt X, apri pull request col risultato". GitHub esegue tutto su un suo server. Tu non fai niente.

Cosa risolve

  • Il sistema gira anche col PC spento, in vacanza, in ferie
  • Costi trascurabili: GitHub Actions gratis fino a 2.000 minuti/mese privati. Una run = 30-60 secondi → ~30 minuti/mese. API Anthropic: ~$0.30-1.50/mese
  • Tu ricevi solo il risultato pronto da approvare

Come si fa

  1. Salvi la chiave API in cassaforte GitHub

    GitHub ha un sistema per credenziali (Secrets). Una volta dentro, sono mascherate — non si possono leggere, solo usare nei workflow.

    gh secret set ANTHROPIC_API_KEY
  2. Apri il workflow nei materiali

    Il file .github/workflows/daily-brief.yml è già pronto. La parte importante:

    on: schedule: - cron: "5 7 * * *" ← "ogni giorno alle 7:05" steps: - lancia Claude Code col prompt in prompts/daily-brief.md - quando finisce, apre una pull request col risultato
  3. Test manuale (per non aspettare fino a domattina)
    gh workflow run daily-brief.yml

    1-2 minuti dopo, una pull request appare nel tuo repo:

    📊 Daily Competitor Brief — auto #42 bot: github-actions nuovo file: briefs/2026-05-08.md (+34 righe)

    Apri, leggi, approvi. Da domattina succede da solo.

Workflow pronto: materiali/.github/workflows/daily-brief.yml. Setup completo: docs/github-actions-setup.md.

Trucco 4 — Delegare task dal telefono in 30 secondi

Idea che ti viene fuori dall'ufficio: "sarebbe bello aggiungere Delta Corp ai competitor". Normalmente: torni a casa, apri PC, lanci Claude, gli spieghi, controlli, salvi. 5-10 minuti.

Soluzione: apri l'app GitHub sul telefono, scrivi una issue (post-it digitale) col task, gli metti l'etichetta claude-task. Una GitHub Action ascolta l'evento "etichetta aggiunta", passa il testo della issue a Claude, lui implementa la modifica e apre pull request. Quando torni a casa hai una proposta pronta da approvare.

Cosa risolve

  • Catturi idee al volo dal telefono senza aprire il PC
  • Hai un backlog visibile: tutte le issue del repo, ognuna con stato (aperta, in lavorazione, chiusa)
  • Anche un collega o un cliente può aprire una issue e Claude la processa
  • Tutto tracciato: tra 6 mesi sai cosa è stato fatto, quando, e chi lo ha richiesto

Come si fa

  1. Crei l'etichetta nel repo
    gh label create claude-task --color "8B5CF6" --description "Task da delegare a Claude"
  2. Imposti il workflow nei materiali

    Il file issue-task.yml. Logica:

    QUANDO: a una issue viene aggiunta l'etichetta "claude-task" ALLORA: 1. prendi titolo + descrizione della issue 2. passali a Claude come prompt 3. fagli implementare la modifica 4. apri pull request che chiude l'issue
  3. Test dal telefono o browser

    Apri il repo → Issues → New issue:

    Titolo: Aggiungi Delta Corp ai competitor Descrizione: Aggiungi Delta Corp come 4° competitor. Sito: delta.example.com Pricing: delta.example.com/pricing LinkedIn: linkedin.com/company/delta Etichetta: claude-task

    Submit. 1 minuto dopo trovi una pull request con il file aggiornato.

Schema: issue = comando, etichetta = submit, pull request = risposta. Se il risultato non ti piace, non approvi e tutto resta com'era.

Workflow pronto: materiali/.github/workflows/issue-task.yml.

Trucco 5 — Controllo qualità automatico prima di salvare

Stai per salvare modifiche. Magari c'è dentro una password copiata per sbaglio, un appunto privato, un FIXME dimenticato.

Soluzione: un "pre-commit hook". È uno script che git esegue automaticamente prima di ogni salvataggio. Lo script manda a Claude le modifiche e aspetta un OK o un BLOCCO. Se Claude trova un problema, il salvataggio fallisce e ti dice cosa correggere.

Cosa risolve

  • Niente più password committate per sbaglio (problema reale: i bot scansionano GitHub in tempo reale)
  • Niente più appunti privati o FIXME dimenticati
  • Funziona in automatico ad ogni salvataggio, senza che ti debba ricordare
  • Se è tutto pulito non disturba: la review è istantanea (~2 secondi)

Come si fa

  1. Attivi lo script nel repo

    Lo script è già pronto nei materiali. Lo copi in .git/hooks/ e diventa attivo:

    cp .github/hooks/pre-commit-claude-review.sh .git/hooks/pre-commit chmod +x .git/hooks/pre-commit
  2. Cosa fa, in italiano

    5 righe che dicono a Claude: "vedi cosa sto per salvare? Rispondi 'OK' se è pulito, 'BLOCCO: motivo' se vedi un problema serio (password, appunti, FIXME)". Se BLOCCO, il salvataggio non parte.

  3. Test pratico

    Provi a salvare una modifica con una chiave API dentro:

    🔍 Claude review in corso... ❌ BLOCCO: rilevata possibile chiave API in config.txt riga 12 Sembra una chiave Anthropic (sk-ant-...). Per bypassare (a tuo rischio): git commit --no-verify

    Disastro evitato. Togli la chiave, salvi di nuovo, passa.

Il bypass --no-verify esiste per i casi in cui sei sicuro che sia un falso allarme. Aggiunge una piccola frizione che ti fa pensare due volte.

Script pronto: materiali/.github/hooks/pre-commit-claude-review.sh.

Altri usi pratici dello stesso pattern

L'esempio del brief competitor è uno dei mille modi in cui questi 5 trucchi si combinano. I casi qui sotto si fanno con gli stessi file dei materiali — cambia solo il prompt.

Lead qualification quotidiana Action schedulata che ogni mattina legge i nuovi lead dal CRM (via API), li qualifica con Claude secondo la tua ICP scritta in CLAUDE.md, ti apre pull request col report.
Audit reputazione settimanale Ogni lunedì alle 9: Claude cerca menzioni del brand sul web, classifica positive/negative/da-rispondere, apre report. Per ogni commento da gestire apri una issue dal telefono col link, etichetta claude-task e Claude prepara la bozza di risposta.
Knowledge base interna aggiornabile da chiunque La wiki vive nel repo. Un collega vede una procedura da aggiornare, apre una issue, etichetta claude-task. Claude aggiorna il file e apre pull request. Niente più "il documento ufficiale è quello che ha Marco sul Drive".
Generazione contenuti social Tieni le idee in un file ideas.md. 3 volte a settimana un'Action prende la prossima idea, Claude la trasforma in post LinkedIn rispettando il tono in CLAUDE.md, apre pull request. Tu approvi e copi su LinkedIn.
Onboarding di nuovi collaboratori Il CLAUDE.md del progetto è anche il manuale di onboarding: chiunque entri nel repo (umano o AI) parte allineato.

Il pattern: regole in CLAUDE.md + copie parallele coi worktree + esecuzione cloud con Actions + backlog con issue + controllo qualità coi hook. Cambia solo cosa fa Claude.

  • GitHub non è solo per programmatori: è uno spazio di lavoro online, gratis, accessibile da telefono

  • Issue + label = backlog di task delegabili dal telefono
