What is a personal AI newsletter

A personal AI newsletter is written by Claude for you only. Your sources, your tone, your frequency. The filter is your brain (5 lines of instructions), not any social's algorithm.

What changes in this variant: no Claude Code, no Agent SDK. Just a ~80-line Python script that explicitly does all the steps: downloads HTML/RSS of the sources, parses to extract new articles, downloads the full text, sends Claude only the clean texts for summarization, saves the markdown.

The idea is maximum transparency: every piece is your code, readable, debuggable. If tomorrow Claude API is down, you know exactly where to swap the piece. If you want to change the HTML parser, you know where to put your hands.

Cost: reduced to the minimum (Claude only sees the already-extracted text, doesn't have to do web fetching itself — you save tokens).

How the system works

📁 THE "NEWSLETTER" FOLDER (minimal Python project) ┌──────────────────────────────────────────────────────┐ │ │ │ 📝 newsletter.py → ~80 lines script │ │ 📝 sources.json → "read these sites" │ │ 📝 prompt.txt → the summary prompt │ │ 📝 state.json → memory of seen URLs │ │ 📝 requirements.txt → anthropic, requests, bs4 │ │ 📝 .env → ANTHROPIC_API_KEY │ │ │ │ 📂 newsletter/ │ │ └── 2026-05-16.md ← today's output │ │ │ └──────────────────────────────────────────────────────┘ │ ▼ 🐍 python newsletter.py (zero agent: every piece of the flow is explicit code) │ ▼ ⏰ cron / Task Scheduler

Script flow, step by step:

  1. requests downloads the HTML of each source
  2. BeautifulSoup extracts article list (title + URL + date)
  3. Python filter: keep only new articles (not in state.json) and recent (≤48h)
  4. For each new article, requests downloads the full HTML, BeautifulSoup extracts the body
  5. anthropic SDK calls the API with the summary prompt + the extracted text
  6. Compose final markdown, write to newsletter/YYYY-MM-DD.md
  7. Update state.json

Zero agent loop, zero tool use, zero magic. Readable procedural code.

Step 1 — Define the sources (HTML or RSS)

The sources.json schema here supports 2 types of source:

{ "sources": [ { "name": "Anthropic News", "url": "https://www.anthropic.com/news", "type": "html", "article_selector": "a[href*='/news/']", "category": "product" }, { "name": "Hacker News (front page)", "url": "https://hnrss.org/frontpage", "type": "rss", "category": "tech" } ] }

For html sources you need a CSS selector that identifies article links (easy to discover with the browser DevTools: right-click → Inspect → identify the article link pattern, copy the CSS selector).

For rss sources no selector: feedparser does everything automatically.

RSS advantage when available: guaranteed stability (the site can change layout without breaking your parser). When a site exposes RSS, always prefer it.

Step 2 — The summary prompt

In this variant the tone lives in prompt.txt (simple text file, not special Markdown). The script reads it once and passes it in the system prompt of the API call.

You are an assistant that summarizes articles for a personal newsletter. TONE RULES: - English, direct, colloquial - Max 3-5 bullets per article, max 1 line each - No generic intros/outros, no marketing adjectives EMPHASIZE: - Concrete numbers, dates, breaking changes - What changes for those who use the product SKIP: - Filler, partnerships without concrete details - Open positions, sponsored events OUTPUT: only the summary bullets, no title (the script adds it).

The script calls the API once per article, passing only the extracted text + this prompt. No agent loop, no tool, no ambiguity.

Step 3 — The newsletter.py script

~80 lines of Python that you read and understand from start to finish.

Philosophy: every step is a Python function with a clear name. fetch_sources(), extract_articles(), summarize_article(), compose_newsletter(). Open the script, read the 4 names, you've understood the flow.

Excerpt of key functions

def extract_articles(source: dict) -> list[dict]:
    """Downloads the source and returns list of articles {title, url, date}."""
    if source["type"] == "rss":
        feed = feedparser.parse(source["url"])
        return [{"title": e.title, "url": e.link, "date": e.published} for e in feed.entries]
    elif source["type"] == "html":
        html = requests.get(source["url"], timeout=15).text
        soup = BeautifulSoup(html, "html.parser")
        return [
            {"title": a.text.strip(), "url": urljoin(source["url"], a["href"])}
            for a in soup.select(source["article_selector"])
        ]


def summarize_article(article: dict, summary_prompt: str) -> str:
    """Downloads the article full text and calls Claude to summarize."""
    full_html = requests.get(article["url"], timeout=15).text
    text = BeautifulSoup(full_html, "html.parser").get_text(" ", strip=True)[:8000]

    msg = client.messages.create(
        model=os.getenv("ANTHROPIC_MODEL", "claude-sonnet-4-7"),
        max_tokens=400,
        system=summary_prompt,
        messages=[{"role": "user", "content": f"Article:\n\n{text}"}],
    )
    return msg.content[0].text

The real script handles errors (timeout, 404), duplicate filters, atomic file writing. But the core is this: download → extract → summarize → compose.

Beyond Anthropic: how to apply the pattern

All 5 use cases from the previous methods work here. The advantage of this variant: you have access to every byte of the flow.

Ultra-aggressive pre-Claude filters Before calling the API, you filter brutally in Python (e.g. keep only articles with at least 3 keywords from your industry in the body). You send Claude 1 article out of 20 → costs reduced to cents/month.
Multi-stage AI pipeline Step 1: call Claude with a small model (Haiku, $0.0003/article) to classify whether the article deserves attention. Step 2: only "approved" articles pass to Sonnet for the actual summary. Save 70% of tokens by using Claude in cascade.
Aggressive caching In the Python script add a disk cache of downloaded articles (if the URL has been downloaded in the last 7 days, reuse). Reduce web traffic and execution time.
Multi-output The same run produces: 1) the markdown newsletter, 2) a LinkedIn POST (200 chars), 3) an entry in a SQLite database for future search. 1 Claude call, 3 different outputs.
