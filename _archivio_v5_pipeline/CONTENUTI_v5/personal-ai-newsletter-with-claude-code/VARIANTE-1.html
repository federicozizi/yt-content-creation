What is a personal AI newsletter

A personal AI newsletter is written by Claude for you only. You choose the sources. You choose the frequency. You choose the tone. The filter is your brain (expressed in 5 lines of instructions), not any social network's algorithm.

What changes in this variant: instead of launching Claude Code from the terminal, you write a Python script that uses Claude Agent SDK — the official library that lets you create Claude agents programmatically. The script runs like any other Python script: you launch it with python newsletter.py, you schedule it with cron.

The final result is identical to the main method: a markdown file in newsletter/YYYY-MM-DD.md. What changes is the control: you have access to the intermediate code, you can add custom logic before/after the generation, you can change every piece.

What we'll build today

Same example as the main method: a daily newsletter on Anthropic's new releases. Every morning at 8, the Python script visits the news page, identifies new articles, summarizes them in markdown.

The output is identical to the main method's (same layout, same style). What changes is how it gets to the result.

How the system works

📁 THE "NEWSLETTER" FOLDER (Python project) ┌──────────────────────────────────────────────────────┐ │ │ │ 📝 newsletter.py → the Agent SDK script │ │ 📝 sources.json → "read these sites" │ │ 📝 CLAUDE.md → "write in this tone" │ │ 📝 state.json → memory of seen URLs │ │ 📝 requirements.txt → claude-agent-sdk, etc. │ │ 📝 .env → ANTHROPIC_API_KEY │ │ │ │ 📂 newsletter/ │ │ └── 2026-05-16.md ← today's output │ │ │ └──────────────────────────────────────────────────────┘ │ ▼ 🐍 python newsletter.py (script that uses Claude Agent SDK as a library) │ ▼ ⏰ cron / Task Scheduler (at 8 every morning it starts by itself)

New pieces compared to the main method:

  • newsletter.py: ~50 lines of Python. Creates a Claude Agent, gives it tools (WebFetch), passes the prompt, saves the output.
  • .env: contains your Anthropic API key (the SDK needs it).
  • requirements.txt: list of Python packages (claude-agent-sdk, python-dotenv).

The CLAUDE.md file with the tone and sources.json with the sources stay identical to the main method. Same philosophy, same pattern.

Step 1 — Define the sources

Identical to the main method. The sources.json file has the same structure.

{ "sources": [ {"name": "Anthropic News", "url": "https://www.anthropic.com/news", "category": "product"}, {"name": "Anthropic Research", "url": "https://www.anthropic.com/research", "category": "research"}, {"name": "Claude Code Changelog", "url": "https://docs.claude.com/en/release-notes/claude-code", "category": "changelog"} ] }

The Python script reads it with json.load() and passes it to the Agent's prompt.

Step 2 — Tone in CLAUDE.md + embedded prompt

In this variant the tone lives in CLAUDE.md (exactly like in the main method) BUT it's passed explicitly to the script's prompt. The Agent SDK doesn't automatically read CLAUDE.md like Claude Code CLI does — you load it yourself.

Key difference: with Claude Code CLI the CLAUDE.md file is loaded automatically at every session. With Agent SDK you load it yourself in the code (open("CLAUDE.md").read()) and concatenate it to the system prompt. It's an extra step, but it gives you total control over what you pass to the model.

Ready file: materiali-variante-1/CLAUDE.md.

Step 3 — The newsletter.py script

The heart of the variant. ~50 lines of Python that do the work.

Script structure: 1) load sources, state, tone; 2) create the Agent with WebFetch tool active; 3) pass the prompt; 4) save the output to the right file; 5) update state.json.

Example (simplified version)

from claude_agent_sdk import Agent
from datetime import datetime
import json, os
from pathlib import Path
from dotenv import load_dotenv

load_dotenv()

ROOT = Path(__file__).parent
sources = json.loads((ROOT / "sources.json").read_text())
state = json.loads((ROOT / "state.json").read_text())
tone = (ROOT / "CLAUDE.md").read_text()

agent = Agent(
    model="claude-sonnet-4-7",
    system=f"You are an assistant that generates daily newsletters.\n\n{tone}",
    tools=["web_fetch"],
)

prompt = f"""
Generate today's newsletter.

Sources: {json.dumps(sources)}
Already-seen articles (don't re-propose): {json.dumps(state["seen_articles"])}

Save the result in newsletter/{datetime.now().strftime("%Y-%m-%d")}.md
Update state.json with the URLs processed today.
"""

result = agent.run(prompt)
print(result.summary)

The real script in the materials is slightly more structured (error handling, logging, checking if the newsletter/ folder exists), but the core is this: Claude Agent + WebFetch tool + your prompt = newsletter generated.

Full script: materiali-variante-1/newsletter.py.

Step 4 — Schedule with cron (or Task Scheduler)

No Claude Routines here: you're using a normal Python script, so you schedule it like any other script.

On Mac/Linux

crontab -e

Add a line:

0 8 * * * cd /path/to/materiali-variante-1 && /path/to/.venv/bin/python newsletter.py >> /tmp/newsletter.log 2>&1

Translation: "every day at 8:00, enter the folder, activate the venv, launch the script, save the logs".

On Windows

Task Scheduler → Create task → Daily trigger at 8:00 AM → Action "Start a program":

  • Program: C:\path\to\materiali-variante-1\.venv\Scripts\python.exe
  • Arguments: newsletter.py
  • Start in: C:\path\to\materiali-variante-1
Advantage of cron vs Claude Routines: cron runs even on headless servers without Claude Code installed. If tomorrow you want to move the system to a $5/month VPS that stays always on, just copy the folder and configure cron. The newsletter arrives even with your PC off.

Full examples: materiali-variante-1/scheduling/crontab-example.txt.

Beyond Anthropic: how to apply the pattern

All 5 use cases from the main method work identically here. The advantage of this variant is that you can add custom logic directly in the Python script.

Pre-Claude filter Before passing the sources to the Agent, you filter brutally in Python (e.g. keep only articles with certain keywords in the title). You save tokens and speed up the run.
Multi-recipients Generate the newsletter once, then in the Python script duplicate it adapting for different audiences (e.g. a "tech" version and a "business" one). 2 output files, 1 Claude call.
Write to database / Notion / Airtable After generating the markdown, the Python script also saves it to Notion API or Airtable API. The newsletter is a layer on top; the data stays structured elsewhere.
Non-time-based triggers Instead of cron, start the script when a webhook arrives (e.g. "every time someone opens an issue on repo X, generate a mini-brief"). The Python script integrates anywhere, cron is only one of the options.
Specialized sub-agent team The same empty-day-rescue + major-update-spotter pattern from the main method (Step 5) is replicated in Python here: 2 additional Agent() instances in the script, one per role, each with its own system prompt. You call them in cascade inside newsletter.py after the main Agent. Advantage over the CLI method: you can orchestrate the flow with explicit Python logic (e.g. "if 0 results AND weekday, only call rescue; weekend, also call a third 'weekly-digest' agent").
